## 1. 变更原因与「测试全绿 ≠ 用户能用」的第二、三次教训

### 1.1 用户本轮原话（逐字对齐，定性为需求变更）

| 用户原话 | 用户真正要解决的问题 | 我们上一轮的做法 |
|---|---|---|
| 「目前会出现 置信度不足，待绑定 这种情况需要处理 因为字段我不可能全部录入 你需要根据label或者placeholder随机生成提示 比如 来源表此字段你未能识别： 你就可以生成 我是来源表测试数据」 | 测试页字段每页不同、数量多，人工逐字段录入 / 绑定不可接受；识别不出来也要产出可核对的测试值，不能留空 | 以「宁可少填也不填错」为由跳过 2 个字段，把诊断面板手动绑定当作补填出口 |
| 「再试一次 按钮文字颜色我看不到 你需要优化调整 以及重新选择区域 按钮长度等UI 你进行优化展示 用天蓝色主题色 以及悬浮的 文字与背景颜色 展示层级也不够 被弹出遮盖了」 | 结果条与悬浮层在真实页面（含弹窗）上必须看得清、点得到 | 深蓝低饱和 Token + 普通浮层层级，未做对比度与 top layer 校验 |

**需求挖掘结论**：用户要的从来不是「填得准」，而是「打开就能用、不用我一个字段一个字段管」。v1 错在要用户先配置，v2 错在要用户先绑定——两次都把工程上的稳妥（安全、准确）凌驾于用户主流程（零操作）之上。

### 1.2 第二次与第三次教训：口径自洽比实现出错更危险

- v2 R2 实测：**P0 = 0、P1 = 0、Bronze**；14 项成功写入 / 0 失败 / 9 跳过；14 条 AC 逐条通过（`QA-V2-REPORT.md` §0 L19、§1 L29-46、§9 L279-294、§10 L300）。
- 但 13 个核心原生控件里 **只有 11 个有值**：「所在单位」`f-org`、「诱饵字段」`f-decoy` 因 low-confidence 被判「待绑定」跳过（§0 L19、§6 D1 L205、§13.2 L404）。用户看到的就是「没填满」。
- 更须诚实记录：QA 曾把「13 个核心控件全非空」的 5 条 FAIL 按 14 条 AC 口径结案为「断言口径假失败」（B1，§0 L21、§7.2 L234）。**被结案的那 5 条断言恰恰是用户真实期望；错的是 AC 口径，不是 QA，也不是实现。**原始 FAIL 保留不删不弱，此刻正好成为 v2.1 的判别依据。
- 第一次教训（`SPEC-v2.md` §1.3 L29-36）是「43 passed / 26 门禁全绿，但默认空白名单全拒绝，开箱不可用」。第二次教训是：**上一轮把「不填错」凌驾于「不用人工逐字段绑定」，实现与一份错误的验收口径完全自洽，测试越绿越证明口径错得一致。这是第二次因验收口径偏离真实使用而返工。**
- **完成定义重置**：判定「可用」的标准是「用户一次手势后，除硬保护控件外是否还有可见控件留空」，不是「实现是否符合一份自洽的 AC 表」。
- **第三次口径偏离（v2.1 交付后实测 P0 回归）**：v2.1 为消除「留空」引入按标签生成的兜底，却把「不留空」当成最高目标，忽略了「值必须合法且类型正确」这一更基本的前提——用户实测常用「姓名」「手机号」被填成「我是请输入网格员姓名测试数据·67」「我是请输入网格员手机号测试数据·87」，手机号还触发页面「请输入正确的手机号」校验。根因是 AC-V2-13 只写了「先归一化到字段类型再调用对应生成器」，未规定「哪些字段必须被识别」：组件库不给 `<label for>` 时 label 为空，单个 placeholder 命中不过 0.6 阈值，常见字段被降为 `unknown` 后走兜底中文模板。实测数字：13 个核心控件 11 个有值（R2）、用户截图 2 个常见字段全部退化为兜底文案。**结论**：兜底只能覆盖**真正无法识别**的字段，绝不能成为常见字段识别失败的遮羞布；由 AC-V2-23 承接。

### 1.3 本轮定性

这是**需求变更，不是缺陷报告**。R2 实现没有 bug，它忠实执行了 `SPEC-v2.md`；要作废的是验收口径本身，故本文不向实现开缺陷单。

## 2. v2.1 产品定义（三句话）

1. 它是一个 Chrome/Edge MV3 扩展，服务内部政务 / OA 测试页，在任意未见过的表单上做到「选一个整体容器，一次填满」——字段语义识别不出来也照填，用户不必逐字段录入或绑定。
2. 用户只需一次手势，系统扫描容器子树内全部可见可填控件：能识别的走 20 类合法假数据生成器，识别不出的按 `label` / `placeholder` 等语义词生成「我是{语义词}测试数据」类兜底值直接填入；零配置、无白名单、无预览确认、无「待绑定」中断。
3. 它只填不提交、零外发、不写日志、不上传，结果可撤销、可逐字段诊断（含「按标签生成」标记），界面为天蓝色主题且浮层永远压在页面弹窗之上，永不点击页面自己的提交按钮。

## 4. 用户流程与兜底生成规则

### 4.1 主流程（零配置一次填满，文字描述，不用 emoji）

1. 全新安装扩展，不做任何配置：不设白名单、不设预设值、不导入文件、不预先录入任何字段。
2. 打开任意含表单的测试页面，展开需要填写的表单或弹窗。
3. 触发一次：点击扩展图标、点击页内悬浮球或按快捷键，三者选其一。
4. 系统自动选定当前最大的可见表单或弹窗容器，扫描子树内全部可见输入控件并逐个填入：语义可识别的走 20 类合法假数据生成器；语义未识别的按 §4.2 取语义词生成兜底值直接填入。全程不出现逐字段拾取、绑定、勾选、预览确认、白名单提示，也不出现「置信度不足，待绑定」中断。
5. 页面出现天蓝色主题精简结果条：显示成功 / 跳过 / 失败计数与常驻说明「仅填入，不提交」；按钮等宽且文案完整；即使页面正展示弹窗或原生 dialog，结果条与悬浮球仍浮于其上、可见可点。
6. 用户可展开逐字段诊断核对（含「按标签生成」标记与取值来源），可点「撤销本次填充」一键回退，可选地用「重新选择区域」框选重填，或在诊断内手动指定类型补填单个字段（非必经）。
7. 用户人工核对后自行决定是否点击页面自己的提交按钮，扩展永不代点。

### 4.2 兜底取值优先级（决定「用哪个语义词」）

按以下顺序取第一个「非空、非纯符号、非纯占位」的值：`label` → `placeholder` → `ariaLabel` → `nearbyText` → `name` → `elementId`。

- **产品级范例（用户原话）**：字段 label 为「来源表」而语义未被识别时，生成「我是来源表测试数据」；模板为「我是{语义词}测试数据」，必须写入文档作为验收基线。模板仅为范例，允许为遵守 §4.3 调整长度，**不得**去掉语义词。
- **全部取不到时**：以「该字段」作语义词，仍须生成并填入；不得留空、不得回退为跳过。理由：统一 team-lead 已下发给前端与 QA 的实现/验收口径。
- 由 `name` / `elementId` 取词时须去除技术前缀与连字符 / 下划线后再入值，避免把 `f-org` 这类标识原样写进测试数据。
- 本优先级只决定语义词来源，**不改变 AC-V2-03 的硬保护判定**；硬保护控件一律不进入兜底生成。

### 4.3 格式约束规则

| 约束 | 规则 |
|---|---|
| 含语义 | 值必须含 §4.2 取得的语义词；模板仅作范例，不得去掉语义词 |
| maxlength | 值长度 ≤ 控件 `maxlength`（无该属性时不受限）；过小时保留语义词可辨识前缀，不得留空或写无语义占位串 |
| number | 合法数字，落在 `min` / `max` 内且符合 `step`（无声明时取范围内整数） |
| date / time | 合法日期 / 时间值，落在 `min` / `max` 内，格式与控件 `type` 一致 |
| email | 合法邮箱格式；无法与中文语义词兼得时以格式合法为先 |
| select | 取页面可见 `option` 之一；无可见 option 时按 pattern 分支处理 |
| checkbox / radio | 写入合法选中态，不把文本值塞进其 `value` |
| pattern | **无法满足时才跳过**，并在诊断标明原因码「pattern 无法满足」；不得写入非法值、不得阻塞其它字段 |
| 同页去重 | 同页多个未识别字段的兜底值互不重复（可加序号或语义词差异化后缀） |
| 不阻塞 | 任一字段兜底失败或跳过，不影响同批其余控件继续填充 |

**约束优先级（防口径打架）**：格式合法 > 语义词可辨识 > 模板字面一致。当控件格式（number / date / time / email / select / checkbox）与「值内含中文语义词」不可兼得时，**必须**以格式合法为先，语义词改由诊断「按标签生成」标记承载（AC-V2-18），**不得**为凑语义词写入格式非法的值。此情形下 AC-V2-16 的「含语义」以「诊断中语义词可辨识」满足，不构成违反。

## 5. 验收标准（EARS）

格式沿用 v2：`While / When / If + 条件，系统必须 + 可观察行为`。**v2.1 生效验收标准共 23 条（AC-V2-01 ~ AC-V2-23）**：AC-V2-01 ~ 12 沿用 `SPEC-v2.md` 原文；AC-V2-13 全文修订（§5.1）；AC-V2-14 局部修订（删除低置信度跳过来源类别、降为可选高级修正，见 §7.1）；AC-V2-15 ~ AC-V2-23 为本文新增 9 条。

### 5.1 修订 AC-V2-13（替换 `SPEC-v2.md` L132 原文，逐字生效）

> **When** 系统为某控件生成取值，**系统必须**先归一化到字段类型再调用对应生成器，身份证通过 GB11643 校验位、手机号符合合法号段、出生日期与性别与证件对应位一致、枚举取自页面可见 option；**If** 推断置信度低于 0.6 或标为 `unknown`，**系统必须**按「`label` → `placeholder` → `ariaLabel` → `nearbyText` → `name` → `elementId`」优先级取语义词生成兜底测试数据并直接填入该控件，**不得**因语义未识别跳过、留空或要求用户逐字段绑定；**不得**硬猜字段类型或写入与控件格式冲突的非法值。

（被替换的原文后半句：「**系统必须**跳过并计入诊断，**不得**硬猜或静默填值」——该口径作废。）

### 5.2 新增 AC-V2-15 ~ AC-V2-23（9 条）

| 编号 | 验收标准 |
|---|---|
| AC-V2-15 | **When** 用户以全新安装、零配置、单次手势触发填充，且选定容器子树内存在推断置信度低于 0.6 或标为 `unknown` 的可见可填控件，**系统必须**在不要求任何前置设置、不要求逐字段绑定、不出现「置信度不足，待绑定」中断的前提下，为该类控件生成兜底测试数据并直接填入；**不得**将其计入「跳过」或留空；**不得**以语义未识别为由阻塞其余控件填充 |
| AC-V2-16 | **When** 系统为语义未识别控件生成兜底值，**系统必须**使该值包含按 §4.2 取得的语义词（控件格式不允许中文入值时，语义词改由诊断标记承载，见 §4.3 约束优先级），产品级范例为 label「来源表」生成「我是来源表测试数据」；**系统必须**保证值长度不超过该控件 `maxlength`，且同页多个未识别字段的兜底值互不重复；**If** `maxlength` 过小致语义词无法完整保留，**系统必须**保留语义词可辨识前缀，**不得**留空或写入无语义占位串 |
| AC-V2-17 | **When** 兜底值写入控件，**系统必须**按控件格式产出合法值：`number` 为 `min`/`max`/`step` 范围内数字、`date` 为合法日期、`time` 为合法时间、`email` 为合法邮箱、`select` 取自页面可见 `option`、`checkbox`/`radio` 为合法选中态；**If** 控件 `pattern` 或其它硬约束无法被任何兜底值满足，**系统必须**且**仅在此情形下**跳过该控件、在诊断中标明「pattern 无法满足」原因码，**不得**阻塞同批其余控件、**不得**因该跳过显示「置信度不足，待绑定」 |
| AC-V2-18 | **When** 用户展开结果条逐字段诊断，**系统必须**对每一个走兜底生成的字段给出可识别的「按标签生成」标记及其取值来源（`label` / `placeholder` 等）、所用语义词与最终填入值；**系统必须**保留该字段的元素定位信息，使用户可核对「哪个字段按哪个标签生成了什么值」 |
| AC-V2-19 | **When** 用户对任一字段主动在诊断面板内手动指定字段类型并单独补填，**系统必须**仅更新该字段、**不得**触发全表单重新填充、**不得**回到主流程强制逐字段绑定；该入口**必须**定位为可选高级修正，**不得**作为完成填充的必经步骤（AC-V2-14 主体继续生效） |
| AC-V2-20 | **While** 结果条、悬浮球与任一主按钮（含「再试一次」「重新选择区域」「撤销本次填充」）展示，**系统必须**采用天蓝色（sky blue）主题，且按钮文字与其背景、悬浮层文字与其背景的对比度**均不得低于 WCAG 2.1 AA 4.5:1**；**不得**出现文字与背景同色或近同色导致「文字颜色看不到」；**不得**使用紫色到粉色渐变 |
| AC-V2-21 | **When** 结果条操作区在标准视口下展示其操作按钮，**系统必须**保证各按钮等宽、文案完整可见、不换行、不被省略号截断、不相互重叠；**If** 按钮文案较长（如「重新选择区域」），**系统必须**由布局容纳而非截断文案；**不得**出现按钮长度不齐或文字被裁切 |
| AC-V2-22 | **While** 页面存在弹窗、浮层或经 `dialog.showModal()` 打开的原生 dialog（top layer），**系统必须**保证悬浮球与结果条仍完整可见、可被点击、不被任何页面弹窗或遮罩覆盖；**When** 用户在该状态下点击悬浮球或结果条按钮，**系统必须**正常响应，**不得**出现「被弹出遮盖」导致不可见或不可点；实现路径由架构师按项目选型锁定，本文不作技术决策 |
| AC-V2-23 | **While** 页面使用常见组件库表单结构，**When** 某控件的 label 缺失但其 placeholder / aria-label / 邻近文本对 20 类权威别名中的常见类型（姓名、手机号、身份证、邮箱、日期等）构成强命中，**系统必须**将其识别为对应字段类型并调用该类型生成器产出合法值；**不得**因 label 缺失降为 `unknown`、**不得**写入兜底中文模板、**不得**产出触发页面格式校验的非法值。 |
