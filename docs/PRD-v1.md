# PRD-v1 表单自动填充工具（初版）

> 形态：Chrome / Edge Chromium 120+ 浏览器扩展（Manifest V3），无后端、无数据库、无登录、无云同步
> 范围：**初版**。只做通用字段类型推断 + 随机合法假数据 + 一键填充（默认只填不提交）+ 可视化拾取器 + 页面指纹规则库
> 依据：`方案评估-表单自动填充工具.md` v0.3（3.1 / 3.2 / 4 / 6 节）、`spec-as-contract.md`、行业基线 `saas-b2b.md` 与 `enterprise.md`、2026-11 联网竞品调研
> 技术基线：`docs/ARCH-v1.md`（2026-11-09，架构师高见远）。本 PRD 已按其第 10 / 11 章、5.3 节与 ADR-003 修订口径，见第 13 节修订记录。
> 本文件是初版的**范围契约**：下游 Spec、设计与实现只按本文件 + 第 8 节验收标准执行；与实现冲突时先改本文件。
> 本轮未写业务代码。

## 1. 问题陈述与目标用户

**问题**：前端开发者在内部政务 / OA 系统的 test / uat 环境做录入测试时，每打开一个表单弹窗都要手工填 20-80 个输入框。表单中文 label、原生 input 与 Ant Design Vue / Element Plus 非原生控件混用、失焦即时校验；更要命的是**不同页面、不同表单的字段集合与数量都不固定**，无法为任一表单预建字段清单。逐字段手输慢、易触发校验红框，直接拖慢测试节奏。现有做法是自己写油猴脚本或逐页配规则，每多一个表单就多一份维护成本。

**主要用户画像**：内部政务 / OA 系统的前端开发者兼自测者，25-40 岁，熟悉 DevTools 与 Vue 生态，能理解「字段类型」概念，但拒绝为每个表单写选择器或脚本。诉求是「任意新页面拿来就能填」。

**次要用户画像**：同团队 QA / 实施人员，技术水平略低，只用悬浮球或快捷键一键填充；推断错时能接受「点几下改绑」，不接受写配置、写正则、写 XPath。

**典型场景**：首次打开一个从未配置过的「新增人才」类弹窗（中文 label、必填即时校验、下拉 / 日期非原生控件、字典枚举、textarea 长文本），需要造一批能通过页面校验的测试记录，人工核对后自己点确定。

**初版交互前提（权限最小化交换，需用户拍板）**：v1 采用 `activeTab` + 用户手势按需注入，安装期无宽泛权限警告。因此悬浮球**不是「打开页面即常驻」**：首次使用必须按一次填充快捷键或点一次扩展图标，页面刷新后需再次触发。若用户更看重「打开页面即常驻」，需改用显式测试域名白名单的 `host_permissions` 并接受安装期权限警告，二者只能选一（ARCH-v1 5.3 / 第 10 章 #4）。此项列入第 15 节待拍板项。

## 2. 竞品分析

差评证据来源：Chrome / Firefox 商店评论、chrome-stats、addons.mozilla.org、ExtSpot / ExtWise 评论分析、Ant Design GitHub issue、TesterHome、CSDN 问答、GreasyFork 真实脚本。厂商自述的能力一律不当作已验证事实。

### 2.1 直接同类工具

| 竞品 | 核心能力 | 优势 | 劣势（来自差评 / 局限） | 定价 | 为何不适配本场景 |
|------|----------|------|------------------------|------|------------------|
| **Fake Filler**（12 万+ 用户，最主流） | 一键把全页 input 填成假数据，靠 **ID / name 属性**配自定义规则，URL profile、设置同步 | 快、快捷键、跨 React/Vue/Angular 宣称可用 | 差评：数据与站点语言不匹配；select 不取正确值；点分属性（name 含点）匹配失败；日期 / 电话 / 文件类控件支持弱；textarea 自定义规则不生效、恒给通用拉丁占位串；「不理解 input type，只给随机文本」；破坏部分网站、控制台刷警告、两年未更新；免费仅 25 个自定义字段 | 免费 25 字段；Pro $3.99/月或 $40/年 | 靠 ID/name 逐字段配规则 = 每页都要配；英文假数据；不校验中文 label；不保证身份证 / 号段 / 枚举合法 |
| **Form Filler – Autofill Forms & Fake Test Data** | Smart matching 读 label / placeholder / name / autocomplete；respect maxlength / pattern / required；fill & submit 默认关 | 识别维度最全、会跳过密码 / 卡 / 验证码、尊重字段约束、纯本地 | 假数据仅 10 种 locale（英美加澳德法西意日葡），**无中文**；以「保存一份 profile 反复填」为主，免费仅 3 条规则、regex 与多 locale 在 Pro；无政务字段合法性（身份证校验位、号段、字典枚举）；无拾取器、无页面指纹规则库 | 免费 1 profile + 3 规则；Pro 一次性买断 | 固定档案模式与「每页字段不同 + 随机合法假数据」相反；中文姓名 / 身份证 / 地址造不出；规则数量限制使多表单成本线性增长 |
| **Form Filler Pro by Zovo**（MV3） | 保存 profiles，一键填、随机测试数据、iframe / Shadow DOM | 纯本地、无账号、MV3、支持受控组件事件 | Chrome 商店 6 评 1.3 星：装完即报 `showUpgradePrompt is not defined`、多个用户「根本不工作」、`Doesn't actually function`、「Paywall in the name of free」；免费 3 profiles + 每天 50 次填充；评分数据在不同站点严重矛盾（1.3 vs 4.6） | 免费受限；Pro 订阅 / Lifetime | 稳定性不达标，测试工具最忌「装了不能用」；仍是 profile 模式；付费墙与内网离线分发冲突 |
| **Automa**（20 万+ 用户，可视化工作流） | 拖拽节点编排自动填表 / 点击 / 抓取，元素选择器拾取，开源 | 免费开源、能力上限高、社区活跃 | 差评：「overcomplicated, almost useless」、学习曲线陡且需 CSS/HTML/JS 基础、文档过时、`Click element` 不工作；SPA 动态渲染下选择器失效（React/Vue 动态哈希 ID、DOMContentLoaded 时序错位、iframe、隐藏元素）；更新后功能崩、内存泄漏、MV3 兼容导致停用；申请 debugger / proxy / tabs 等 10 项权限（风险评分 89） | 开源免费 + 付费高级功能 | 每个表单要手工编排一条工作流 = 每页一份配置；权限过重不适合政务内网；维护成本随表单数线性增长 |

> 补充参照：QuickForm / Filliny 一类新工具已主打「派发框架兼容事件 + 录制回放」，证明受控组件事件派发是行业公认门槛；但它们同样围绕 profile / URL 结构回放，且假数据为英文，未覆盖中文政务字段，故不单列为可替代方案。

### 2.2 替代方案（用户现在可能在用的做法）

| 替代方案 | 能做到什么 | 差评 / 局限 | 为何不适配本场景 |
|----------|------------|-------------|------------------|
| **Chrome 原生 Autofill** | 静态 HTML 表单的姓名 / 地址 / 支付卡一键填 | 第三方 50 站点实测仅 38% 完全成功，政务 / 税务表单 1/6、招聘门户 2/10；设计于 2011 面向静态 HTML；对 React/Vue 受控组件直接写 `.value` 不派发事件，**看起来填了但提交是空的**；只在页面加载扫描一次，联动显隐 / 分步表单新增字段全漏；自定义 dropdown / date-picker 完全无法交互；政务 / 银行门户常用 `autocomplete="off"` 主动禁用 | 只能填本人真实保存资料，不能生成随机合法假数据；内部系统无标准 autocomplete 属性、中文 label 无语义映射；非原生控件与受控组件全部失手 |
| **Playwright / Selenium / RPA** | 脚本化批量造数、可跑 CI | TesterHome 实测「复合组件假成功」：Ant Design / Element / Vant 的下拉、树选、级联、日期、滑块不是原生，click 完代码报绿、DOM 变了但**表单内部状态没提交**；`fill()` 不触发 Vue `v-model`，须逐字符 `pressSequentially`；Ant Design 官方 issue #58161：Select / DatePicker 为 body 级 portal、`data-testid` 不转发、`fill()` 受控不可靠、日期格式随 locale 变；每表单写脚本，启动慢、需运行环境 | 方案 v0.3 已判定：适合「一次造 200 条」的批处理，不适合日常随手填一个弹窗；每页字段不同 = 每个表单一份脚本 |
| **Tampermonkey / 油猴填表脚本** | 0.5 天可验证可行性，直接改 DOM | 与 SPA 生命周期不同步（DOMContentLoaded 时字段未渲染）、Vue Router 跳转后失效、动态 name/id 含随机哈希、Shadow DOM 难命中；GreasyFork 真实脚本（自动填写完成任务表单）`@match` 锁死单个 URL、直取 `.el-form` 内部 Vue 实例、硬编码 3 个字段名、`setTimeout` 1000ms 硬等；ScriptCat「表单填充助手」靠预设规则 + 保存档案，且明确提示「不要在考试、银行、医疗等关键系统使用」 | 一份脚本对应一个页面一个表单，正是本需求明确否定的「写死字段清单」做法；无合法性保证、无跨页面复用、维护成本随表单数线性增长 |
| **Faker.js / Mockaroo（数据源）** | 生成看起来像真的中文姓名 / 地址 / 公司名，支持固定种子 | 是库 / 在线服务，不是填表工具；`fakerZH_CN` 的 `phone.number()` 给的是固话格式（如 043-62477966），不是 11 位手机号，要自己拼号段；官方文档注明并非所有方法都本地化；**无身份证生成器**、不保证 GB11643 校验位、不理解业务枚举、不管字段间一致性（出生日期 / 性别与证件位） | 只解决「像中文」，不解决「能通过页面校验」；且仍需自己写代码把值塞进表单 |

## 3. 为什么现成工具不能直接解决本场景（重点）

| 本场景的硬约束 | 现成工具为何失效 | 我们必须做什么 |
|----------------|------------------|----------------|
| **内部政务 / OA，test / uat 内网域名** | Chrome Autofill 在政务类表单 1/6 成功；政务门户常用 `autocomplete="off"`；商业扩展的付费墙 / 账号 / 云同步在内网不可用；油猴脚本明确警告勿用于关键系统 | 纯本地、离线可用、站点白名单 + 环境标识校验，非白名单拒绝填充；不申请高危权限；不产生任何外发请求 |
| **中文 label，字段名无语义、常无 for/id 关联** | Fake Filler 靠 ID/name 配规则，遇到动态哈希 ID 与点分属性即匹配失败；Chrome Autofill 靠英文 autocomplete token 启发式；Faker 只造中文值，不识别中文 label | 以中文别名词典 + 多特征加权打分为主（label > placeholder > name/id > aria-label > 邻近节点 > 表单行结构），配正则特征（`maxlength=18`、`type=tel/email/date`）；识别「字段类型」而非「字段名」 |
| **Ant Design Vue / Element Plus 非原生控件** | Fake Filler 差评「select 不取正确值」；Chrome Autofill 对自定义 dropdown / date-picker 完全无法交互；AntD 官方确认下拉为 body 级 portal、日期 `fill()` 不可靠；TesterHome 记录「脚本报绿、业务没生效」 | 组件库最小适配（**v1 仅 2 库指定主版本的 select / date-picker**）：不假设选项在触发器 DOM 子树内，日期按页面 `valueFormat` 生成字符串；赋值后**回读验证状态已更新**，否则判失败；超出范围跳过并记 `E_UNSUPPORTED_CONTROL` |
| **Vue 受控组件** | 裸 `el.value = x` 只改 DOM 不更新状态；Chrome Autofill / 多数扩展 / Playwright `fill()` 都栽在这里 | ISOLATED world 取原型原生 setter 直接 `.call(el, value)` + 冒泡 `input` / `change`（textarea 用对应原型 setter、checkbox / radio 用 `click()`），末尾回读校验；**禁止裸赋值、禁止依赖 `el.__vue__` / `__vueParentComponent` 等组件实例私有字段**（MV3 world 隔离读不到，Vue 3 生产构建默认不暴露） |
| **字段每页都不同、数量不定** | 所有 profile / 规则 / 工作流 / 油猴脚本方案都要求「每个表单先配一份」，成本随表单数线性增长；Automa 选择器还会因改版失效 | 零配置直接填；规则库按页面指纹归档且**只存例外修正**，不存全量字段映射；结构漂移时提示重新校验而非静默沿用 |

**一句话**：现成工具都在解决「把一份已知数据填进一个已知表单」，本需求是「把随机合法数据填进一个从没见过的表单」。

## 4. 我们的差异化

1. **按字段类型而非字段名工作**：任意新页面零配置即可填充，第 N 个表单接入成本趋近于 0；规则只存「这个页面这几个字段的修正」。
2. **中文政务字段的合法性**：中文姓名 / 单位 / 地址 + 身份证 GB11643 校验位 + 11 位合法号段 + 出生日期与性别和证件位一致 + 枚举必须命中页面 option 集合 + 固定种子可复现。这是英文假数据工具与 Faker 中文 locale 共同的市场空白。
3. **为受控组件与非原生控件正确性负责**：走 ISOLATED world 的 DOM 主路径（原生 setter + 冒泡事件），不依赖框架组件实例私有字段；赋值后回读校验，失败可定位、可一键重新拾取；不承诺 100% 全自动，但把修正成本压到「点几下」。
4. **安全边界即产品特性**：仅测试域名、默认只填不提交、配置不上传 / 不写日志 / 导出可脱敏、权限最小化（安装期无宽泛权限警告）——这让它能进政务内网，而同类商业扩展不能。**不向用户承诺「加密存储」**。

## 5. 初版功能清单（简化 RICE 排序）

**RICE 口径**：`Score = (Reach x Impact x Confidence) / Effort`。Reach = 该能力覆盖的日常填充任务占比（1-10）；Impact = 0.25/0.5/1/2/3；Confidence = 50%/80%/100%（有竞品差评或方案基线支撑取 80-100%）；Effort = 相对人月（1=半天，10=3 个月以上）。
**重要判断**：RICE 只用于排序。**能力闭环的必要条件不因分数低而砍掉**——类型推断与赋值引擎分数中等，但缺了它们「填不对 / 填不进」，产品即不可用。P0 按依赖分层，不按分数截断。

### 能力簇 A：识别（把控件变成字段类型）

| 编号 | 功能 | 优先级 | R | I | C | E | Score | 说明 |
|------|------|--------|---|---|---|---|-------|------|
| A1 | 页面控件全量扫描（L1） | **P0** | 10 | 3 | 100% | 2 | 15.0 | 不预设数量与位置；过滤 hidden / disabled / readonly / file / password / captcha；作用域限定到最近表单容器；**仅顶层帧与同源 iframe，跨源 iframe v1 不做** |
| A2 | 中文优先字段类型推断（L2） | **P0** | 10 | 3 | 80% | 5 | 4.8 | **字段类型枚举以 `docs/contracts/field-types.json` 为唯一权威**（20 类 + `unknown` 哨兵，哨兵不是生成器目标，PRD 不另列清单）；中文别名词典 + 加权打分 + 正则特征 + 页面 option 枚举抓取；**低于置信度阈值标 `unknown`，不硬猜** |
| A3 | 可视化拾取器（L3 例外覆盖） | P1 | 6 | 2 | 80% | 3 | 3.2 | 悬浮高亮、点选改绑类型；只存增量修正；可展示的信息只有 DOM 文本与属性，无组件实例信息 |
| A4 | 页面指纹规则库 | P1 | 7 | 2 | 80% | 4 | 2.8 | URL 模式 + 表单结构 hash；只存例外；漂移提示重校验；JSON 导入导出 |

### 能力簇 B：生成（按类型产出合法值）

| 编号 | 功能 | 优先级 | R | I | C | E | Score | 说明 |
|------|------|--------|---|---|---|---|-------|------|
| B1 | 约 20 类合法假数据生成器 | **P0** | 10 | 3 | 100% | 3 | 10.0 | 身份证校验位 / 号段 / 日期与性别一致 / 字典枚举；生成器与页面解耦；非法值不写入，返回 `E_VALIDATION_REJECTED` |
| B2 | 固定种子可复现 | **P0** | 6 | 1 | 100% | 1 | 6.0 | 同种子同页面数据集完全一致，便于复现问题 |

### 能力簇 C：执行（安全地把值写进去）

| 编号 | 功能 | 优先级 | R | I | C | E | Score | 说明 |
|------|------|--------|---|---|---|---|-------|------|
| C1 | 受控组件赋值引擎 + 组件库最小适配 | **P0** | 10 | 3 | 80% | 5 | 4.8 | ISOLATED world 原生 prototype setter + 冒泡事件 + 回读校验；**v1 仅覆盖 Ant Design Vue / Element Plus 指定主版本的 select 与 date-picker**；cascader / 远程搜索 select / 富文本 / IME composition 类跳过并记 `E_UNSUPPORTED_CONTROL` |
| C2 | 一键填充 + 填充计划预览 + 默认不提交 | **P0** | 10 | 3 | 100% | 2 | 15.0 | 用户手势（快捷键 / 点扩展图标）触发后按需注入，非页面打开即常驻，刷新后需再次触发；预览可逐项跳过；绝不自动触发提交按钮 |
| C3 | 安全护栏 | **P0** | 10 | 2 | 100% | 1 | 20.0 | 站点白名单 + 环境标识校验 + 默认只填不提交 + **`chrome.storage.local` 隔离存储 + 不上传 + 不写日志 + 导出脱敏（不得宣称加密）** + 零外发 + 权限最小化 |
| C4 | 填充诊断报告 | P1 | 7 | 1 | 80% | 2 | 2.8 | 成功 / 跳过 / 失败分类 + 失败元素定位与错误码，供一键重新拾取 |
| C5 | 动态联动与分批调度 | P1 | 6 | 2 | 50% | 5 | 1.2 | 基础字段填完触发 change，等待联动稳定再填新增字段；分批 + 限速 + 单次总量上限，避免打爆远程唯一性校验与卡死主线程 |

> **与方案 v0.3 第 4 节的偏差（已由架构确认）**：v0.3 把「Ant Design Vue / Element Plus 适配层、动态联动」放在 P2。但本场景的政务表单主体就是这些非原生控件，若初版不支持，零配置可用率会塌到接近 0，P0 交付即无价值。故本 PRD 把**最小可用集**上提到 P0。架构 ARCH-v1 第 10 章 #5 已确认此范围：**v1 仅 2 库指定主版本 + 2 类控件（select / date-picker）**，其余控件跳过并给 `E_UNSUPPORTED_CONTROL`；完整适配、远程搜索下拉、级联、跨页面会话留后续。这是初版内部优先级调整，不新增后续版本功能。

## 6. MVP 范围（收敛）

**v1 = 三个能力簇各取最小闭环，一次交付：A1 + A2 + B1 + B2 + C1 + C2 + C3（P0），紧随 A3 + A4 + C4 + C5（P1）。**

- P0 定义「可用」：在从未配置过的真实政务表单上，一键填入合法值、通过即时校验、不误填、不提交（交互前提见第 1 节）。
- P1 定义「可维护」：推断错了点几下能改、改版了能提示、填充结果可诊断。A3 / A4 属 team-lead 锁定的初版范围，与 P0 同属 v1，仅实现顺序靠后。
- 完成定义：第 8 节 8 条验收标准全部满足 + 第 14 节端到端验证通过 + 误填计数与自动提交计数均为 0。

## 7. 明确不做清单（每条带原因）

| 不做 | 原因 | 归属 |
|------|------|------|
| 预设固定值（固定姓名、固定身份证等） | 用户明确这是初版，后续才可能加；但数据层必须抽象为可替换来源，初版仅实现随机来源，后续加来源不改识别 / 填充 / 执行层 | v1.1（方案 3.2 `DataProvider` / `presets` schema 已预留，ADR-003） |
| Excel / CSV 导入指定数据 | 同上；导入属于指定数据来源，与「通用类型推断 + 随机」是不同价值主张 | v1.2 |
| 自动提交 / 批量连续造数 | 用户明确「默认只填不提交，人工核对后自己点确定」；政务系统误提交后果不可逆，且会放大误填风险 | 后续（保留开关位，初版 UI 不暴露） |
| 团队共享后端 / 云同步 / 账号登录 | 形态已锁定无后端 / 无数据库 / 无登录；政务内网禁止数据出本机 | 不排期 |
| 为单个表单预建全量字段映射表 | 与「字段每页都不同」根本冲突，是竞品 / 油猴脚本被淘汰的做法 | 永久不做 |
| 验证码 / 滑块、文件上传、电子签名、富文本复杂内容、绕过登录与权限、生产环境写入 | 方案 v0.3 第 0 节已列为 Out-of-Scope；非填充问题，且涉及安全与合规 | 永久不做 |
| 跨页面会话保持 / 多步骤连续录入（同一条记录跨页一致） | 方案 v0.3 第 7 节列为待澄清项；**架构 ARCH-v1 第 11 章已判定 v1 out-of-scope**；初版先把单页闭环做扎实 | v1 不做，后续版本评估 |
| 项目内 SDK 钩子（`window.__FORM_FILLER__`）/ 组件实例精准填充通道 | ARCH-v1 2.1 / 2.4 判定双重不可行：ISOLATED world 读不到 `el.__vue__` / `__vueParentComponent`，Vue 3 生产构建默认不暴露；且 SDK 钩子需页面主动改代码暴露，与「不改业务代码」的初版前提冲突 | P3 可选（页面主动暴露，非扩展偷偷读），v1 不做 |
| cascader / 远程搜索 select / 富文本 / IME composition 类控件、跨源 iframe | ARCH-v1 第 10 章 #5 / #7 判定高成本或帧级权限限制；非原生控件无稳定公开 API、版本差异大 | v1 不做，诊断报告给 `E_UNSUPPORTED_CONTROL` |
| 页面打开即自动注入、常驻悬浮球（不依赖用户手势） | 与 `activeTab` 权限模型互斥：不申请 `host_permissions` 就无法自动注入（ARCH-v1 5.3 / 第 10 章 #4） | **待用户拍板**：v1 默认不做；若选常驻则改用显式白名单 `host_permissions` 并接受安装期权限警告 |
| 100% 全自动准确率承诺 | 方案 3.1 已定零配置可用率目标 70-80%；低置信度字段走点选绑定，不硬猜、不静默填 | 不承诺 |

## 8. 验收标准（EARS）

格式：`When / While / If + 条件, 系统必须 + 可观察行为`。覆盖核心成功流、错误流、权限、并发、边界。

| 编号 | 验收标准 |
|------|----------|
| **AC-1** | **When** 用户在白名单内的测试页面按下填充快捷键或点击扩展图标（用户手势触发按需注入），**系统必须**扫描最近表单容器内全部可填控件、过滤隐藏 / 禁用 / 只读 / 文件 / 密码 / 验证码类控件，并生成可逐项勾选跳过的填充计划预览；若可填控件数为 0，**系统必须**展示空状态提示而非报错或直接执行；若用户未做手势或页面刷新后未重新触发，**系统必须**提示需再次触发。此阶段不得修改任何控件值。 |
| **AC-2** | **When** 用户确认填充计划，**系统必须**按计划写入各控件值，且**不得**点击任何提交 / 确定按钮、**不得**触发表单提交；**填充计划预览 / 填充结果 / popup 三处的主按钮文案不得出现「提交 / 确定 / 保存并提交」**；填充过程中每个控件写入后**必须**回读确认值已生效。 |
| **AC-3** | **While** 目标控件由 Vue / React 受控，或为 v1 适配范围内的 Ant Design Vue / Element Plus 非原生控件，**系统必须**走 ISOLATED world 的 DOM 主路径（原生 prototype setter + 冒泡 `input` / `change` 事件派发），**禁止**依赖 Vue / React 组件实例私有字段；赋值后**必须**以 ISOLATED world 三层可观测证据（`domValueMatched` / `frameworkStateMatched` / `validationCleared`）+ 两渲染帧回滚检测判定值与校验态已生效，三项齐备且无回滚才算成功，任一项不满足记 `E_READBACK_MISMATCH` 并计入失败；超出适配范围的控件**必须**跳过并记 `E_UNSUPPORTED_CONTROL`，不得判为成功。 |
| **AC-4** | **When** 系统为某控件生成取值，**系统必须**先归一化到字段类型再调用对应生成器，且身份证号必须通过 GB11643 校验位校验、手机号必须符合合法号段、出生日期与性别必须与身份证对应位一致、枚举值必须取自该页面可见的 option 集合；同一种子下多次生成**必须**结果完全一致；违反约束的值**不得**写入。 |
| **AC-5** | **If** 某控件推断置信度低于阈值 **0.6（已锁定：ARCH-v1 §17.2 / `LIMITS.CONFIDENCE_THRESHOLD` = 0.6；契约唯一权威为 `docs/contracts/types.ts` 与 `rules.schema.json` 的 `weights.confidenceThreshold`）**，**系统必须**把类型标为 `unknown`、在填充计划预览中列出供用户点选绑定，**禁止**硬猜或静默填值；**If** 页面结构 hash 与已存规则不匹配，**系统必须**提示「规则可能失效，是否重新校验」并给出元素定位，**禁止**静默沿用旧规则。 |
| **AC-6** | **If** 当前页面域名不在测试站点白名单内，或目标控件落在表单容器之外（如搜索框、筛选条件），**系统必须**拒绝填充并给出明确提示（记 `E_SITE_NOT_ALLOWED`），**不得**写入任何值。 |
| **AC-7** | **When** 填充过程中某字段触发联动导致新增控件或远程搜索下拉异步加载，**系统必须**等待联动稳定后再填充新增控件，且**必须**分批派发事件让出主线程并限速；**不得**使用固定 `setTimeout` 判断稳定，**不得**因集中派发导致页面失响应或打爆异步唯一性校验。 |
| **AC-8** | **When** 用户在拾取器里把某个控件改绑为另一字段类型，**系统必须**只把这一条修正按页面指纹（URL 模式 + 表单结构 hash）归档为增量规则，**不得**覆盖全局别名词典、**不得**生成全量字段映射表。 |

## 9. 边界条件与非功能需求

### 边界条件

| 状态 | 要求 |
|------|------|
| 空状态 | 页面无可填控件 / 弹窗未打开 → 空状态提示，不报错、不执行 |
| 错误状态 | 单控件赋值失败 / 联动超时 / 规则失效 → 记入诊断报告并定位，不中断其余控件填充 |
| 加载状态 | 弹窗异步挂载、远程搜索下拉加载中 → 等待稳定再填，超时标记失败 |
| 边界值 | 单页 20-80 控件（目标支持上百）→ 分批调度 + 单次总量上限，不卡死主线程 |
| 并发 | 用户重复触发填充 → 后一次取消或排队前一次，不得叠加写入 |
| 离线 | 全部能力本地运行，断网可用；不依赖任何网络请求 |
| 手势与注入 | 采用 `activeTab` 最小权限：首次填充需用户手势（快捷键 / 悬浮球 / action），页面刷新后需再次触发；不声明 `host_permissions`，安装期无权限警告 |
| 权限拒绝 | 非白名单域名 / 用户未授权标签页 / 页面刷新后未重新触发手势 → 明确拒绝或提示需再次触发，不降级为「尽力填」 |

### 非功能需求

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 20-50 控件规模从触发到填充完成 ≤ 3s；单控件赋值 ≤ 50ms；不引起被测页面可感知卡顿 | P0 |
| 安全性 | 仅测试域名白名单；默认只填不提交；`chrome.storage.local` 是隔离存储**不是加密存储**，v1 不宣称加密，改为不上传 / 不写日志 / JSON 导出可脱敏；零外发请求；权限最小化（仅 `storage` / `activeTab` / `scripting`，不申请 `debugger` / `proxy` / `tabs`） | P0 |
| 兼容性 | Chrome / Edge Chromium 120+（MV3，ARCH-v1 2.6 / 4.1 锁定）；页面侧兼容 Vue 2 / Vue 3 / React 受控组件的 **DOM 主路径**，不依赖组件实例私有字段；**v1 仅覆盖 Ant Design Vue 与 Element Plus 指定主版本的 select / date-picker，其余非原生控件返回 `E_UNSUPPORTED_CONTROL`，并在诊断报告提供一键重新拾取**；跨源 iframe v1 不做 | P0 |
| 注入策略 | `activeTab` + 用户手势按需 `executeScript` 注入，不声明 `host_permissions`、不静态声明 `content_scripts`，安装期无宽泛权限警告；代价：首次需按一次快捷键 / 点图标，页面刷新后需再次触发（见第 1 节与第 15 节待拍板项） | P0 |
| 隔离性 | 内容脚本不得污染页面全局对象、不得向控制台刷警告、不得因扩展自身异常阻塞被测页面 | P0 |
| 可靠性 | 单控件失败隔离；规则与代码分离（JSON 导入导出）；结构 hash 归一化剔除动态 `id` / 随机 class / `data-v-*` / 时间戳，避免漂移误报 | P1 |
| 可访问性 | 扩展自身 UI 键盘可达、对比度达 WCAG 2.1 AA 基本合规 | P2 |
| 图标方案 | **Lucide 唯一图标库**，Vue 侧 `@lucide/vue@1.70.0`，SVG 随扩展离线内联打包、不依赖 CDN；`lucide-vue-next` 已被 npm 标记 deprecated，**禁止入依赖**；图标以名称标注，**禁止 emoji 作为功能图标**，功能含义一律用文字描述（如「注入图标」「字段拾取图标」「诊断报告图标」）；禁止引入第二套图标库或自绘 SVG | P0 |
| 设计风格 | 企业软件稳健风（深蓝 / 藏青主色、信息密度高、操作路径短、每屏强调色 ≤ 2 处）；所有破坏性操作提供撤销与二次确认；**禁止紫色到粉色渐变类高饱和方案**；不使用空洞占位文案 | P0 |
| 国际化 | 初版 UI 仅中文；代码层字段类型标识用 ASCII，为后续多语言留结构余地，不实现 i18n | P2 |

## 10. 数据埋点方案

**关键产品判断**：本产品无后端、政务内网运行、方案 v0.3 明确「不上报任何数据」，因此传统云埋点（注册 / 留存 / 付费转化）**不适用且禁止**。改为**本地诊断计数**：只统计可量化的过程指标，用于验证第 11 节成功指标，用户可在 options 页查看与一键清空。与 ARCH-v1 6.0 的 `Logger` 约束一致：日志只记字段名 / 类型 / 结果码，不写身份证、手机号等原始值。

| 事件类别 | 本地计数事件 | 说明 |
|----------|--------------|------|
| 触发 | `fill_triggered`、`fill_plan_confirmed` | 填充次数、预览到确认的转化 |
| 激活 | `first_core_action`（首次完成一次填充） | 新用户是否跑通闭环 |
| 质量 | `field_inferred`、`field_unknown`、`field_skipped`、`field_failed`、`picker_rebind`、`rule_hash_drift` | 零配置可用率、低置信度占比、修正成本、改版漂移 |
| 结果 | `fill_completed`、`error_occurred` | 成功率、耗时、异常分类 |

**实现要求**：事件命名 `{对象}_{动作}`；属性仅含字段类型、控件类别、成功 / 跳过 / 失败原因码、耗时、页面指纹 hash；**不采集字段取值、不采集姓名 / 身份证等敏感值、不采集 URL 明文（用 hash）、不采集 IP、不采集页面原始输入内容**；存储全部在本地，零网络上报；options 页须有**常驻采集边界声明**（写明上述全部不采集项），且**导出的配置 JSON 不含诊断计数**。

## 11. 初版成功指标

| 指标 | 目标 | 验证方式 |
|------|------|----------|
| 零配置可用率 | 在 ≥ 3 个从未配置过的真实政务 / OA 页面上，首次填充无需拾取修正即正确填入的控件占比落在 **70-80% 目标区间（下限 ≥ 70%）**；**分母只算 v1 适配范围内且可填的控件**，超范围控件按 `E_UNSUPPORTED_CONTROL` 跳过并单列统计、不计入本指标，避免指标被不支持控件污染；低置信度字段必须走点选绑定，**不承诺全自动、不硬猜** | 本地 `field_inferred` / `picker_rebind` 计数 + 人工复核 |
| 合法性通过率 | 生成值被页面自带即时校验判定为合法的字段占比 **≥ 95%**（身份证 / 手机号 / 日期 / 枚举） | 端到端验证逐字段检查红框 |
| 单表单填充耗时 | 20-50 控件规模，触发到完成 **≤ 3s**，无页面卡顿 | `fill_completed` 耗时 |
| 修正成本 | 推断错误的控件，通过拾取器完成一次类型改绑 **≤ 3 次点击**，且只存增量 | 拾取器走查 |
| 权限与交互 | 安装期**无**「读取和更改所有网站上的数据」类宽泛权限警告；首次手势注入与刷新后重新触发均有明确提示 | 安装流程走查 + 端到端验证 |
| 安全硬指标 | 误填次数（搜索框 / 筛选框 / 密码 / 验证码 / 只读禁用被写入）**= 0**；自动提交次数 **= 0**；外发请求数 **= 0** | 诊断报告 + 本地计数 + 网络面板 |
| 改版可感知 | 页面结构 hash 变化后 **100%** 给出「规则可能失效」提示，不静默沿用旧规则 | 人为增删一个控件后重跑 |

## 12. 内嵌已知坑（来自竞品差评与架构核实，作为硬约束）

| 踩过的坑 | 本初版必须 / 禁止 |
|----------|-------------------|
| Fake Filler 差评「不理解 input type，只给随机文本」、textarea 恒给通用拉丁占位串 | **必须**按字段类型分发生成器；**禁止**任何字段一律填通用随机串；长文本备注类也要给中文可读短句 |
| Fake Filler「数据与站点语言不匹配」、Form Filler 仅 10 locale 无中文、`fakerZH_CN` 的 `phone.number()` 是固话格式、Faker 无身份证生成器 | **必须**输出中文姓名 / 单位 / 地址；手机号**必须** 11 位合法号段；身份证**必须**含 GB11643 校验位；**禁止**直接照搬英文假数据库默认输出 |
| Chrome Autofill / Playwright `fill()` / TesterHome「脚本报绿、业务没生效」；React `inputValueTracking` 覆写实例 value setter | **禁止**裸 `el.value = x`；**必须**取原型原生 setter `.call(el, value)` + 冒泡 `input` / `change`，末尾回读校验（`E_READBACK_MISMATCH`）；textarea / checkbox / radio 各用对应原语 |
| ARCH-v1 2.1 / 2.4：ISOLATED world 读不到 DOM expando；Vue 3 生产构建默认不暴露 `__vueParentComponent` | **禁止**把 `el.__vue__` / `__vueParentComponent` / React 私有 props 写进任何 v1 契约；**禁止**承诺「读组件实例精准填充」；精准通道只能是 P3 页面主动暴露的 SDK 钩子 |
| Ant Design issue #58161（下拉为 body 级 portal、日期 `fill()` 不可靠）、TesterHome 复合组件假成功 | **禁止**假设下拉选项在触发器 DOM 子树内；日期**必须**按页面 `valueFormat` 生成；**禁止**用固定 `setTimeout` 判断联动稳定；超范围控件跳过并记 `E_UNSUPPORTED_CONTROL` |
| Automa / 油猴脚本「选择器失效、每页写一份脚本」 | **禁止**为单个表单建全量字段映射表；**禁止**用静态 CSS / XPath 路径作规则主键；规则按页面指纹归档且只存增量 |
| Automa 申请 10 项权限（风险评分 89） | **必须**权限最小化，**禁止**申请 `debugger` / `proxy` / `tabs` 等与填表无关的高危权限 |
| 政务 / 银行门户 `autocomplete="off"`、油猴脚本警告勿用于关键系统 | **必须**站点白名单 + 环境标识校验，非白名单拒绝填充（`E_SITE_NOT_ALLOWED`） |
| Fake Filler「破坏网站、控制台刷警告」、Automa「更新后功能崩」 | **必须**隔离内容脚本，**禁止**污染页面全局对象与控制台，**禁止**因扩展异常阻塞被测页面 |
| ARCH-v1 第 9 章：`chrome.storage.local` 是隔离存储非加密存储 | **禁止**向用户承诺「加密存储」；改为不上传 / 不写日志 / 导出可脱敏 / 默认不提交 |

## 14. 端到端验证步骤（完成定义）

1. 在 Chrome / Edge（Chromium 120+）以未打包方式载入 MV3 扩展，**确认安装期没有「读取和更改所有网站上的数据」类宽泛权限警告**；在 options 页把一个 test / uat 域名加入白名单。
2. 打开该域名下一个**从未配置过**的表单弹窗，需含：中文 label、原生 input、Ant Design Vue 或 Element Plus **指定主版本**的 select 与 date-picker、textarea、至少一个搜索框（在表单容器外）、**至少一个 v1 不支持的控件**（如 cascader 或远程搜索 select）。记录填充前控件数。
3. 按填充快捷键（首次手势，确认 content script 被按需注入）→ 断言出现填充计划预览、低置信度字段以 `unknown` 列出供点选绑定，且此时**无任何控件值变化、提交按钮未被点击**（AC-1 / AC-2 / AC-5）；**刷新页面后断言需再次触发手势**（AC-1）。
4. 确认计划 → 断言应填控件全部获得值、失焦后即时校验无红框、提交按钮仍处于未点击状态、不支持的控件出现在失败项且带 `E_UNSUPPORTED_CONTROL`（AC-2 / AC-3）。
5. 逐项核对身份证校验位、手机号号段、出生日期与性别和证件位一致、下拉值命中页面 option 枚举；用同一种子重复步骤 3-4，断言数据集完全一致（AC-4）。
6. **错误 / 边界流**：把域名移出白名单再触发 → 断言拒绝填充且给出 `E_SITE_NOT_ALLOWED` 明确提示（AC-6）；打开一个无可填控件的页面 → 断言空状态提示而非报错（AC-1）；人为改绑一个字段类型 → 断言只新增一条按页面指纹归档的增量规则（AC-8）。
7. **改版 / 联动流**：选中会触发新增字段的下拉，断言新增字段在联动稳定后被填充且页面未卡顿（AC-7）；人为增删一个控件改变结构 hash → 断言提示「规则可能失效」并给出重新拾取入口，未静默沿用旧规则（AC-5）。
8. **完成判定**：AC-1 至 AC-8 全部通过 + 误填计数为 0 + 自动提交计数为 0 + 外发请求数为 0 + 安装期无宽泛权限警告 + 诊断报告中失败项可一键定位到元素。验证中暴露的问题沉淀为回归用例，新坑回写第 12 节。

## 15. 交给下游的约束（本 PRD 不做的决策留在此点名）
