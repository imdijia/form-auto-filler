## 1. 变更原因与 v1 验收口径失效说明

### 1.1 根因：把工程完整性当成了产品可用性

v1 把「站点白名单授权、计划预览逐项勾选、填充前二次确认、多次手势、26 条门禁」当作产品质量本身，而用户要的只有一件事：选一个整体容器，一次把里面所有可见输入框填满。用户说「一个输入框一个输入框选择，增加了工作量」，指向的是问题（逐字段操作是负担），不是功能建议；我们却把它实现成了必经链路。这是范围做偏，不是 bug。

### 1.2 真实需求逐字对齐

| 用户原话 / 澄清 | v1 实际做法 | v2 处理 |
|---|---|---|
| 「是否可选择一个整体 dom，你自动识别下面所有可视化输入表单内进行填充」 | 限定「最近表单容器」，但仍要求逐项预览勾选 | 容器整体选定，子树一次填满 |
| 「还需要一个输入框一个输入框选择，增加了工作量」 | 拾取器 / 逐项绑定 / 逐项勾选为必经步骤 | 全部移出主流程 |
| 「零配置一键全填」 | 白名单 + 预览 + 确认 + 多次手势 | 一次手势直接填充 |
| 「填不进去 / 填错」 | 被当作待排查 bug | 判定为范围做偏导致的开箱不可用，列为 v2 首条验收起点 |

### 1.3 测试全绿 ≠ 用户能用（本次教训）

v1 Phase 4 交付「43 passed / 0 failed、264+ 断言、26 条门禁全绿」，但那只验证了「在人工预置好前置状态之后，引擎能否正确工作」，没有验证「用户能不能正常使用」：

- `QA-PHASE4-REPORT.md` §3.1 记录白名单是通过 `chrome.storage.local.set('faf.siteAllowlist.v1', ['localhost'])` 直接写入 storage 配置的；E2E 从未走过「全新安装 → 未做任何配置 → 首次触发」这条真实路径。
- 同报告 §3.2 的 E2E-06 专门验证「移出白名单后拒绝填充」，即默认空白名单等于默认全拒绝；对应 `SPEC-v1.md` §12 第 2 步把「options 里加入白名单」写成验收前置步骤、`PRD-v1.md` AC-6 把拒绝写成硬性门禁。用户开箱触发得到的是拒绝，这正是「填不进去」。
- `PRD-v1.md` AC-1 / AC-5 要求预览逐项勾选、低置信度字段必须人工点选绑定后才继续；未绑定前字段不填，用户看到的是「没填满 / 填错」。
- 26 条门禁与记分卡衡量的是工程完整度，不是首次使用成功率。门禁数量与可用性无关。

**结论**：失效的是验收口径，不是实现。v1 的完成定义（AC-1~8 + §12 端到端 + 26 条门禁）整体作废，不能用它宣告 v2 可用。

### 1.4 v2 验收口径重置

- 起点必须是「全新安装、零配置、无任何 storage 预置、首次手势」。
- E2E 禁止通过直接写 storage 或调用内部状态构造前置条件，必须从真实 UI 手势进入。
- 判定「可用」的唯一起点是 AC-V2-01；引擎层单元测试全绿只是必要条件，不是完成定义。
- 四条安全底线（只填不提交、零外发、不写日志、不上传）继续作为一票否决项。

## 2. v2 产品定义（三句话）

1. 它是一个 Chrome/Edge MV3 扩展，服务内部政务 / OA 测试页，在任意未见过的表单上做到「选一个整体容器，一次填完」。
2. 用户只需一次手势（点扩展图标、点页内悬浮球或按快捷键，三选一），系统自动选定当前最大的可见表单或弹窗容器，扫描其子树内全部可见输入控件并直接填入合法中文假数据，不需要白名单、不需要逐字段绑定、不需要预览确认。
3. 它只填不提交、零外发、不写日志、不上传，结果可撤销、可逐字段诊断，永不点击页面自己的提交按钮。

## 4. 用户流程（文字描述，不用 emoji）

### 4.1 主流程（零配置一键全填）

1. 全新安装扩展，不做任何配置：不设白名单、不设预设值、不导入文件。
2. 打开任意含表单的测试页面，展开需要填写的表单或弹窗。
3. 触发一次：点击扩展图标，或点击页内悬浮球，或按快捷键，三者选其一即可。
4. 系统自动识别当前最大的可见表单或弹窗容器，扫描其子树内全部可见输入控件，直接写入合法假数据。全程不出现预览逐项勾选、不出现二次确认、不出现白名单提示、不要求第二次手势。
5. 页面出现精简结果条：显示成功 / 跳过 / 失败计数与常驻说明「仅填入，不提交」；提供「撤销本次填充」与「展开逐字段诊断」。
6. 用户人工核对后自行决定是否点击页面自己的提交按钮，扩展永不代点。

### 4.2 备选流程（重新选择区域）

1. 在结果条点击「重新选择区域」，进入框选模式。
2. 鼠标在页面上移动时，候选容器以低饱和描边高亮并就近显示文字提示；此阶段页面控件值不发生任何变化。
3. 点击目标容器（弹窗、表单区或任意 DOM 节点），系统立即以该容器为范围执行填充，回到结果条。
4. 按 Esc 退出框选模式，不产生任何写入。

### 4.3 界面与图标约束

- 结果条沿用 v1 深蓝低饱和设计 Token 与纯文本状态标签；禁止紫色到粉色渐变，禁止 emoji 作功能图标，禁止空洞占位文案。
- 图标只取自 `@lucide/vue@1.70.0`，离线内联，以文字命名，不引入第二套图标库。
- 结果条主按钮文案不得出现「提交 / 确定 / 保存并提交」。

## 5. 验收标准（EARS，共 14 条）

格式沿用 v1：`While / When / If + 条件，系统必须 + 可观察行为`。AC-V2-01 为团队锁定原文，逐字不改。

| 编号 | 验收标准 |
|---|---|
| AC-V2-01 | While 用户在全新安装的扩展上、未做任何配置，When 在任意测试页面触发填充，系统必须识别可见表单容器并完成填充，且不要求任何前置设置 |
| AC-V2-02 | **When** 用户触发填充（自动选定容器或框选容器），**系统必须**扫描该容器子树内全部可见输入控件并逐个尝试填充，**不得**只填部分控件、**不得**要求用户逐字段拾取、绑定或勾选 |
| AC-V2-03 | **When** 扫描到不可见（hidden / display:none / visibility:hidden）、禁用、只读、文件上传、密码、验证码 / 滑块类控件，**系统必须**跳过并计入「跳过」，**不得**写入任何值；**不得**填充容器之外的搜索框与筛选条件 |
| AC-V2-04 | **While** 填充流程执行中及结束后，**系统必须**永不点击页面提交 / 确定 / 保存按钮、**不得**触发表单 `submit` 事件；触发入口、结果条、popup 三处主按钮文案**不得**出现「提交 / 确定 / 保存并提交」 |
| AC-V2-05 | **When** 向受控组件或 v1 适配范围内的非原生控件写入值，**系统必须**按 focus → 原生 prototype setter → `InputEvent(bubbles, composed, inputType)` → change → blur/focusout 的加固序列赋值，首次失败后多路径重试（组件库策略 / 重发 InputEvent / composition 序列），任一路径成功即停；**系统必须**以「DOM 值匹配 + 两个渲染帧后值稳定」判定成功，`validationCleared` **必须**从硬失败判据降级为 advisory 证据，只记入 evidence 供诊断展示、**不得**单独导致 `verified=false`；**If** 控件被标为 `E_UNSUPPORTED_CONTROL` 但仍可见，**系统必须**再试一次通用原生赋值、**不得**直接放弃；**不得**把「事件已派发」判为成功 |
| AC-V2-06 | **When** 任一字段填充失败或被跳过，**系统必须**在结果条可展开的逐字段诊断中给出该字段的元素定位信息与失败 / 跳过原因码，用户据此可定位到具体控件 |
| AC-V2-07 | **When** 用户点击结果条「撤销本次填充」，**系统必须**把本次成功写入的控件恢复到填充前原值且**不得**提交；**If** 页面跳转导致快照失效，**系统必须**将撤销按钮置灰并文字说明原因 |
| AC-V2-08 | **While** 扩展运行（含触发、填充、诊断展示），**系统必须**不发起 fetch / XHR / WebSocket / EventSource / sendBeacon 请求、**不得**加载远程字体、**不得**引入统计 SDK、**不得**上传任何数据、**不得**输出日志；结果条计数仅为本次会话运行态展示 |
| AC-V2-09 | **While** 用户触发一次填充，**系统必须**以单次手势直接完成填充，**不得**要求站点白名单授权、**不得**出现填充计划预览逐项勾选、**不得**出现填充前二次确认、**不得**要求第二次手势 |
| AC-V2-10 | **When** 用户点击「重新选择区域」，**系统必须**进入框选模式，hover 时高亮候选容器并就近文字提示，点击某容器即以该容器为范围执行填充；**When** 用户按 Esc，**系统必须**退出框选且不产生任何写入 |
| AC-V2-11 | **If** 用户未启用排除 / 限制清单（默认关闭），**系统必须**默认放行所有页面并正常填充；**If** 用户显式配置排除项，**系统必须**仅对该项生效，**不得**将其恢复为全站拒绝门禁、**不得**以 `E_SITE_NOT_ALLOWED` 阻塞未配置页面的填充 |
| AC-V2-12 | **If** 选定容器子树内可填控件数为 0，**系统必须**展示空状态文字提示，**不得**报错、**不得**写入任何值 |
| AC-V2-13 | **When** 系统为某控件生成取值，**系统必须**先归一化到字段类型再调用对应生成器，身份证通过 GB11643 校验位、手机号符合合法号段、出生日期与性别与证件对应位一致、枚举取自页面可见 option；**If** 推断置信度低于 0.6 或标为 `unknown`，**系统必须**跳过并计入诊断，**不得**硬猜或静默填值 |
| AC-V2-14 | **When** 某字段被计入「跳过」（含推断置信度低于 0.6 / `unknown` 及不可填排除项），**系统必须**在结果条展开的逐字段诊断中列出该字段的元素定位信息与跳过原因码，并允许用户在诊断面板内手动指定字段类型后**单独补填该字段**；**不得**回到主流程强制逐字段绑定、**不得**阻塞其余控件填充、**不得**因补填触发全表单重新填充 |

## 6. 明确不做清单

| 不做 | 原因 |
|---|---|
| 固定一套个人信息 / 预设值 | 用户本轮未选择，不要加回来 |
| Excel / CSV 导入指定数据 | 用户本轮未选择，不要加回来 |
| 跨页面连续录入、会话保持、多步骤连续造数 | 用户本轮未选择，不要加回来 |
| 自动提交、批量连续造数 | 只填不提交是不可协商底线 |
| 组件实例精准填充通道、页面侧 SDK 钩子 | v1 已双重否决，禁止写回 |
| 本地加密存储 | v1 已否决（隔离存储非加密存储），禁止写回；改为不上传 / 不写日志 / 不落原始值 |
| 团队共享后端 / 云同步 / 账号登录 | 无后端形态，政务内网数据不出本机 |
| 为单个表单预建全量字段映射表 | 与「字段每页不同」根本冲突 |
| 验证码 / 滑块、文件上传、电子签名、富文本复杂内容、绕过登录、生产环境写入 | 非填充问题且涉合规 |
| 逐字段拾取 / 绑定 / 勾选作为主流程必经步骤 | 本轮核心删除项 |
| 填充计划预览、填充前二次确认、站点白名单前置授权 | 本轮核心删除项 |
| 紫色到粉色渐变、emoji 作功能图标、Lorem ipsum / Welcome to 类空洞文案 | 团队 P0 绝对规则 |
| 重新选型图标库 | 沿用已锁定的 `@lucide/vue@1.70.0` |
| 100% 全自动准确率承诺 | 低置信度一律跳过，不硬猜；但不再阻塞主流程 |
