## 0. 设计输入与前置判断

### 0.1 需求提取

| 维度 | 结论 |
|---|---|
| 产品类型 | Chrome / Edge MV3 浏览器扩展，开发者效率工具，无后端、零网络请求 |
| 目标受众 | 前端 / 测试人员，在内部政务、OA 系统里造测试数据；DevTools 是肌肉记忆 |
| 使用环境 | 宿主页是 Vue + Ant Design Vue / Element Plus 风格的政务表单，字段多、控件类型杂、页面各不相同；初版 P0 含两类组件库最小适配 |
| 风格关键词 | 克制、精准、可信、可核对、不抢宿主页面 |
| 转化目标 | 无转化。目标是「填之前能核对、填之后能追责」，降低误填与静默填错 |
| 明确不做 | 营销页、自动提交、云同步、账号体系、数据上报、预设字段值 UI、CSV 导入 UI、自动提交开关（v1） |

## 1. 同类工具 UI 调研

联网调研 6 类参考，覆盖任务要求的三类（表单填充扩展 / Chrome 原生 Autofill / DevTools 元素拾取器）并补充两类（密码管理器内联菜单 / 扩展 popup 尺寸规范）；另吸收 PM 在 PRD §12 汇总的竞品差评硬约束（见 §1.3）。

### 1.1 调研矩阵

| 参考 | 界面形态 | 可借鉴 | 要避开 |
|---|---|---|---|
| **A. Fake Filler**（40 万用户，最主流测试填表扩展） | toolbar 图标一键填充 + 快捷键 + options 页自定义字段 | 一键填充与快捷键双通道；内置忽略规则（CAPTCHA / hidden / disabled / readonly）；URL 级配置归档（对应本项目页面指纹规则库）；零配置 sensible defaults | **一键全填、无预览、无确认**：填完才知道填错，政务系统的搜索框被误填会污染查询条件；自定义字段依赖手写 id/name 属性，政务表单 label 与 id 常无关联；无本次结果反馈、无诊断；自定义字段数量做付费墙 |

### 1.2 调研收敛出的 5 条硬约束

1. **预览即闸门**：绝不做 Fake Filler 式「一键全填」。所有写入必须先经过填充计划预览并点击确认，这是政务场景防误填的第一原则。
2. **三列映射表**：计划预览与诊断报告统一用「页面控件 / 推断字段类型 / 将填入的值」三列，直接借 DevTools Autofill 面板，用户零学习成本。
3. **作用域优先于规则**：默认只扫描最近的表单容器，从源头把搜索框、筛选框排除在外，比事后靠关键词黑名单更可靠。
4. **激活态可感知**：拾取器必须像 DevTools Inspect 一样有常驻工具条与明确高亮，不能是「静默进入某种模式」。
5. **结果可追责**：成功/跳过/失败三项都要带数量与原因，跳过列原因、失败列元素定位，失败项给重新拾取入口（基线 §3.1 诊断报告、§6.8 规则失效自愈）。

### 1.3 竞品差评教训转为设计目标（PM PRD §12 / 团队消息）

| 竞品踩过的坑 | 转化为本项目的设计目标 | 落点 |
|---|---|---|
| Automa 差评「overcomplicated, almost useless」、需 CSS/HTML/JS 基础、学习曲线陡 | 拾取器改绑**不超过 3 次点击**完成；绑定面板只给「字段类型」中文列表 + 搜索，**不暴露选择器 / 正则 / XPath / DOM 路径输入框**；不要求用户写任何配置语法 | §4.5、§7.5 |
| Automa / 油猴脚本「选择器失效、每页写一份脚本」 | 规则主键是页面指纹，界面上不出现静态选择器编辑；「页面规则」Tab 只展示可读的控件标签与修正结果 | §4.4 |

## 2. 设计方向

### 2.1 对标品牌与设计语言

| 角色 | 对标 | 借什么 |
|---|---|---|
| 主对标 | **Chrome DevTools（Elements / Autofill 面板）** | 三列映射表、拾取器高亮与 tooltip、键盘优先、状态即信息。目标用户每天在用，熟悉感最强 |
| 主对标 | **Linear / Raycast 的命令式面板** | popup 与预览面板的列表骨架、即时筛选、键盘可达、150ms 反馈（只借交互骨架，不借深色主题） |
| 视觉对标 | **Ant Design 政务/OA 表单** | 扩展 UI 与宿主页同语系：同样的输入高度、同样的蓝色按钮、同样的 1px 分隔线，避免「另一个产品」的割裂感 |
| 辅参考 | Stripe Dashboard（表格与状态文本）、Notion（分组留白） | 数据密度与分组节奏 |

**设计语言一句话**：像 DevTools 一样精准，像政务表单一样克制。扩展 UI 是宿主页面的「工具层」，不是另一个产品；它的存在感应低于宿主页内容，只在用户主动唤出时变清晰。

**视觉主题关键词**：克制、精确、可核对、可追溯、不打扰。

**氛围**：浅色冷灰白底，深藏青作为唯一强调色，1px 发丝线分隔，无渐变、无发光、无毛玻璃、无装饰图形。所有信息靠文字与位置表达。

### 2.2 配色基调（政务深蓝、低饱和）

配色来源：`color-palettes.md` 第 5 套「B2B 服务深海军」与第 28 套「法律权威蓝金」融合，叠加 `enterprise.md` 的 `#1e3a5f` 政务藏青，全局压低饱和度并给中性色加微量蓝倾向（chroma 0.005 至 0.015，符合 OKLCH 凝聚规则）。

### 2.3 字体

配对来源：`typography-pairings.md` 第 11 套「Corporate Trust（企业/政府/无障碍优先）」+ 第 22 套「中文简体」+ 第 7 套等宽。所选字族均不在反射拒绝清单（Fraunces / Newsreader / Lora / Playfair / Space Grotesk / IBM Plex / DM Sans / Inter 作展示字 / Plus Jakarta Sans 等）内。

```css
--font-body:    "Noto Sans SC", "Source Sans 3", "Microsoft YaHei", sans-serif;
--font-display: "Noto Sans SC", "Lexend", "Source Sans 3", sans-serif;
--font-mono:    "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
```

**工程约束（重要，交给架构师与前端）**：

- 产品 UI 绝大多数为中文，中文优先走 `Noto Sans SC`；拉丁字符（字段类型 slug、种子、元素路径、快捷键）走 `--font-mono`。标题靠**字号 + 字重**建层级，不靠第二字族硬凑。
- **content script 注入到宿主页的 UI 不加载任何外部字体文件**：政务系统常有严格 CSP，且外部字体会污染宿主页、增加注入体积。注入层使用 `font-family: var(--font-body)`，靠系统字体栈回退；只有扩展自有页（popup / options）打包字体子集。
- `Noto Sans SC` 在扩展页按常用 3500 字子集化，`font-display: swap`，预连接 + 仅加载 400 / 500 / 700 三档。
- 不使用 serif（Product 寄存器 + 政务工具，衬线体会显得像公文编辑器而非调试工具）。

**字号阶梯（8 级）**：`--text-xs` 12 / `--text-sm` 13 / `--text-base` 14 / `--text-md` 16 / `--text-lg` 18 / `--text-xl` 20 / `--text-2xl` 24 / `--text-3xl` 32（px，rem 表达）。

- popup 与页内面板正文 14px（列表密集），options 长表单正文 16px，**任何界面正文不低于 13px**。
- 行高：正文 1.6，标题 1.25，列表行 1.4；行宽 50 至 75 字符（中文约 25 至 37 字）。
- 字重三级：Read 400（正文）/ Emphasize 510（小标题、按钮、表头）/ Announce 590（页面标题）。
- 字距：正文 0；小字 0.01em 至 0.02em；ALL CAPS 与 kbd 0.08em；标题 24px 以上 -0.01em。
- 数字用 `font-variant-numeric: tabular-nums`，保证「成功 18 / 跳过 3 / 失败 1」对齐不跳动。

### 2.4 圆角 / 间距 / 层级 / 动效

**间距**：严格 4px 网格，仅允许 `4 8 12 16 20 24 32 40 48 64`。禁止 5 / 7 / 13 / 15 / 22 / 30 等非标值。

**圆角**：`--radius-sm` 4（kbd、小型标记）/ `--radius-md` 8（按钮、输入、列表行）/ `--radius-lg` 12（卡片、面板、抽屉）/ `--radius-pill` 9999（仅悬浮球）。**卡片上限 12px**，禁止 24px 以上过度圆滑。

**卡片**：`var(--surface)` + `1px solid var(--border)` + `--radius-lg` + 无默认阴影（Hairline First）。hover 只改 `border-color` 到 `--accent`，不做 lift、不做 scale。列表密集处用 `divide-y`（`--border-soft`）与负空间分组，**不用同尺寸卡片网格**。

**层级（z-index）**：MV3 content script 注入 UI 需要极高值且隔离。

| 层 | z-index |
|---|---|
| 宿主页内容 | 页面自身 |
| 注入层根容器（Shadow DOM） | `2147483000` |
| 拾取器高亮 overlay | `2147483645` |
| 拾取器工具条 / tooltip | `2147483646` |
| 填充计划预览抽屉 / 绑定面板 | `2147483647` |

**动效**（MOTION_INTENSITY 2）：

| 场景 | 时长 | 属性 |
|---|---|---|
| 按钮 / 勾选 / 状态切换 | 150ms | `color` / `background-color` / `border-color` / `opacity` |
| 面板展开、抽屉滑入 | 200ms | `transform` / `opacity` |
| 退场 | 100ms | 同上 |

- 缓动统一 `--ease-standard: cubic-bezier(0.2, 0, 0, 1)`。**禁止带负控制点的过冲回弹缓动（bounce / elastic 类及其 cubic-bezier 变体）、禁止超过 400ms 的动效**。
- 只动 transform / opacity / 颜色，禁止动画 `width` / `height` / `top` / `left` / `margin`。
- 悬浮球无呼吸脉冲、无发光、无入场编排。
- `prefers-reduced-motion: reduce` 时所有 transition 降至 0.01ms，拾取器高亮改为静态描边。

### 2.8 交互基线（PRD §9 / saas-b2b.md，v1.1 新增）

**undo 可撤销**：填充是「影响面大但非破坏性」的操作，必须可撤销。

- 执行填充前，由 content script 对每个计划内控件**快照原值**（含空值），仅存于内存会话，不落盘、不写入本地计数。
- **恢复原值的通道（v1.2 定稿，ARCH-v1 第 2 章 / §16.4）**：撤销复用 Filler 写入时的 **ISOLATED world DOM 通道**——原生 prototype setter 回写快照值 + 冒泡 `input` / `change` 事件，让受控组件的监听同样收到变更；**不得依赖 Vue 组件实例通道**（架构已判定 MV3 ISOLATED world 读不到组件实例，生产构建默认不暴露，该路径不可行）。界面与文案只说「恢复填入前的值」，不宣称「回滚组件状态」。
- **非原生控件的撤销（ARCH-v1 §16.4）**：`select` / `date-picker` 等不能只对隐藏 `input` 写回原值，否则显示文本与组件内部 state 不一致，会变成新的假成功。这类控件必须复用**当初填充它的同一个 P0 `FillerStrategy`** 恢复（select 恢复原 option、date-picker 按原 `valueFormat` 恢复字符串），并同样走 `StateVerifier` 回读校验后才翻「已撤销」。底层仍是上面的 DOM 通道，不引入组件实例通道。
- 快照仅存 content script 内存会话、不落盘、不进 `faf.counters.v1`、不进导出 JSON；含空值（空字符串是有效快照），已有值被 `hasValue` 保留的控件不进快照。失效条件为 `isConnected` 假 / `structureHash` 变化 / 页面跳转 / 弹窗关闭，一律给「页面已变化，无法撤销」。
- 填充完成后，预览面板底部 sticky 与 popup 结果区各提供一个 `f-undo-fill` 文字按钮「撤销本次填充」；点击后恢复各控件原值，已有值保留的控件不受影响，状态列回到「待填」、汇总计数清零，并给纯文本「已撤销本次填充」。
- undo 只在本次页面会话内有效；页面跳转 / 弹窗关闭导致快照失效时，按钮置灰并给纯文本「页面已变化，无法撤销」，不假装可撤销。
- 撤销本身为可逆操作，不需要二次确认。

**二次确认**（破坏性操作，按钮命名破坏，不用泛化「确定」）：

| 操作 | 按钮文案 |
|---|---|
| 删除页面规则 | 「删除 5 条规则」 |
| 清空本地诊断计数 | 「清空本地统计」 |
| 恢复默认配置 | 「恢复默认配置」 |
| 开启「跳过预览直接填充」 | 「开启跳过预览」 |
| JSON 导入存在覆盖冲突 | 「覆盖 3 条并导入」 |

**批量选中态**：预览面板「全选 / 反选 / 仅看待填」+ 汇总行实时计数；options 表格勾选后顶部浮出批量操作栏（enterprise.md 规范）。

**快捷键**：`Alt+Shift+F/G/H/P` + `Esc`，见 §4.1；快捷键冲突给明确降级提示，不静默失败。

**隔离性（PRD §9 L171 / §12）**：注入层 Shadow DOM 隔离；不改宿主页 DOM 结构（只加兄弟 overlay）；不注入全局样式；不写页面全局对象；**不向宿主页控制台输出任何日志或警告**；扩展自身异常不得阻塞被测页面；自动弹出大窗属于干扰，一律禁止。

**按钮文案禁令（默认只填不提交）**：预览面板、填充结果面板、popup 结果区不得出现「提交」「确定」「保存并提交」「下一步：入库」等诱导业务表单提交的主按钮或文案。options 页「已保存」仅指扩展自身配置写入本地，需与业务表单提交明确区分，可写作「配置已保存到本机」。

## 4. 五界面：交互流程与布局要点

### 4.1 界面一：页面悬浮球 / 快捷键触发（content script 注入）

**定位（v1.2 修正）**：**按需注入入口，不是「打开页面即常驻」**。悬浮球与拾取器只在用户手势触发注入后才出现；页面刷新 / 标签页重载后注入失效、悬浮球消失，必须再次触发。唤出后只打开填充计划预览，不直接执行填充。

**权限与触发链（v1.2，ARCH §5 按需注入模型）**：v1 采用 `permissions: ["activeTab", "scripting", "storage"]`，**不声明 `host_permissions`**，安装期不出现「读取所有网站数据」宽泛警告。权限分两层：`activeTab` 决定「能不能注入」，业务白名单决定「注入后允不允许填」，界面上不把两者混为一谈。

```
[未注入态] 页面已打开，页面上没有任何扩展 UI
   |
   | 用户手势：Alt+Shift+F / Alt+Shift+P / 点击工具栏扩展图标
   v
[注入] activeTab 临时授权 + chrome.scripting.executeScript
   |
   v
[挂载] WXT createShadowRootUi 创建 Shadow DOM UI（悬浮球 / 拾取器）
   |
   v
[可用态] 悬浮球出现 -> 业务白名单校验 -> 打开填充计划预览
   |
   | 页面刷新 / 标签页重载 / 导航
   v
[回到未注入态] 悬浮球消失，需再次用户手势触发
```

**两处引导文案（v1.2，PM 要求具体不空洞）**：

| 场景 | 位置 | 文案 |
|---|---|---|
| 首次使用（未注入态） | popup 顶部常驻提示条 + options 白名单配置完成后的提示 | 「首次使用请按 `Alt` `Shift` `F`，或点击工具栏扩展图标，在当前页唤出填充面板」 |
| 页面刷新后 | popup 顶部提示条（检测到上次注入已失效时） | 「页面已刷新，请再次按 `Alt` `Shift` `F` 触发」 |

- 两处文案中的快捷键用 `f-kbd` 分键展示（等宽，0.08em 字距），不用图标、不写「欢迎使用」「快速开始」之类占位。
- 若用户改选「打开页面即常驻」方案（PRD L268 列为待拍板的权限交换），这两处引导取消；当前按 `activeTab` 方案实现。
- **禁止**把悬浮球画成页面打开就存在、禁止自动注入、禁止注入前在宿主页渲染任何扩展 UI。

**布局**：注入后悬浮球位于右下角，距视口边 24px，直径 48px（≥44×44 触摸目标），可拖拽并记忆位置。折叠态为 32px 字标 `F`，透明度降低但不用发光。注入 UI 挂在 WXT `createShadowRootUi` 创建的独立 Shadow DOM 根容器下，z-index `2147483000`。

**交互流程**：

| 用户操作 | 视觉反馈 |
|---|---|
| 首次 `Alt+Shift+F` / 点击扩展图标 | 执行注入并出现悬浮球，同时打开填充计划预览（主路径） |
| 页面刷新后再次触发 | 同上；此前 popup 已给「请再次按快捷键触发」提示 |
| 单击悬浮球 | 打开填充计划预览面板（**不填充**） |
| 悬浮球 hover | 150ms 背景提亮到 `--accent-hover`，无位移、无阴影放大 |
| 右键悬浮球 | 小型菜单：重新识别 / 可视化拾取 / 打开配置页 |
| `Alt+Shift+G` | 仅识别**当前表单作用域**（对应 Mocknik 分级） |
| `Alt+Shift+H` | 仅识别**当前焦点字段所在表单行** |
| `Alt+Shift+P` | 注入并进入可视化拾取器 |
| `Esc` | 关闭任何浮层 / 退出拾取器；不卸载注入（刷新才卸载） |
| 双击（可在 options 开启） | 按上次计划直接填充。**默认关闭**，开启时需二次确认并明确文案「跳过预览直接填充」 |

**安全态**：域名不在业务白名单时，悬浮球为禁用态（`--surface-warm` 底 + `--meta` 图标），tooltip 纯文本「仅测试域名可用」，不提供任何填充入口。注入被 `activeTab` 拒绝时给纯文本「当前标签页未获得授权，请点击工具栏扩展图标后重试」，不静默失败。

**快捷键冲突处理**：commands API 未生效时，popup 顶部给纯文本「快捷键未生效，请在扩展快捷键设置中修改」+ 文字链接，不静默失败。

**交互基线落点（v1.2）**：

- **undo**：悬浮球右键菜单增加「撤销上一次填充」文字入口（与预览面板、popup 同一动作）；会话快照失效时置灰并给纯文本「页面已变化，无法撤销」。
- **二次确认**：开启「双击跳过预览直接填充」必须二次确认，按钮文案「开启跳过预览」，并明确写出「此后双击将不经过计划预览直接写入」。
- **批量选中态**：本界面不承载列表，批量操作在计划预览完成（§4.2）。
- **快捷键**：4 组唤出 + `Esc` 关闭 + `Ctrl+Z` 撤销；重复触发填充时后一次取消或排队前一次，不叠加写入。
- **六态（含未注入态）**：未注入（页面无扩展 UI，popup 给首次引导）/ 空（点击后打开空状态计划面板）/ 加载（「正在识别控件」）/ 错误（「识别失败，点击重试」）/ 成功（打开计划预览）/ 权限拒绝（禁用态 + 明确原因）。
- **隔离性**：WXT Shadow DOM UI 隔离、不改宿主页 DOM 结构、不注入全局样式、不写页面全局对象、不向宿主页控制台输出日志或警告、扩展异常不阻塞被测页面；不自动弹出任何大窗。

**信息架构**（三列映射表借 DevTools Autofill 面板；v1.2 补 `unknown` 待绑定态与 `E_UNSUPPORTED_CONTROL` 超范围控件单列）：

**控件类型差异（v1.2，对齐 ARCH-v1.1 §17.6 / `contracts/types.ts`）**：每行在控件标签之后插入一枚 `f-control-type` **纯文本标签**，取值固定为 `ControlType` 5 类中文映射 `输入框 / 下拉 / 日期 / 文本域 / 其他`（对应 `input` / `select` / `date` / `textarea` / `other`，L1 扫描必须返回）。这是「这是什么控件」的**类型维度**；字段类型（`FieldType`，20 类 + `unknown`）是另一个正交维度，预览行两列分别展示、互不覆盖。

- **「超范围控件」不是控件类型，是处置状态**：`E_UNSUPPORTED_CONTROL` 只在结果面板单列分组（§4.6），不能塞进 `f-control-type` 的取值。cascader、远程搜索 select 按 ARCH §17.6 归类为「下拉」（`select`），但**归类不等于纳入 v1 适配范围**，二者只以「下拉」控件类型 + `E_UNSUPPORTED_CONTROL` 单列呈现，不混进失败、不占成功率分母。
- **v1 支持范围**：原生 `input` / `textarea` / `select`，以及 **Ant Design Vue / Element Plus 指定主版本的 `select` 与 `date-picker`**。富文本、自定义复合控件等**一律标 `E_UNSUPPORTED_CONTROL` 跳过，不预留填充态**（PM PRD v1.1 收窄结论）。
- **信息边界（ARCH ISOLATED world）**：控件类型标签只依据 **DOM 结构与标准属性**做启发式判定，可读信息仅限 `label` / `placeholder` / `name` / `id` / `aria-label` / 邻近文本 / `maxlength` / `pattern` / 枚举 `option`。**读不到 Vue 组件实例与框架字段名，界面不得出现「自动识别组件库」「读取组件内部状态」之类暗示**。
- 标签样式：`--text-xs`、`--fg-2`、字重 510，`--surface-warm` 底 + `--radius-sm`，**无图标、无语义色、无彩色胶囊**。控件类型是「这是什么控件」，状态是「这次填得怎样」，两者视觉语言必须可分但都不靠颜色。
- 该标签在**填充计划预览、执行中状态列、诊断报告明细、popup 结果明细**四处保持一致。
- 筛选框支持按控件类型过滤（如只看「下拉」），便于在组件库适配出问题时集中核对。

**`unknown` 待绑定态（v1.2，PRD AC-5）**：字段类型枚举以 `docs/contracts/field-types.json` 为权威（20 类 + `unknown` 哨兵，`confidenceThresholdDefault: 0.6`）。**置信度低于 0.6 一律标 `unknown`，不硬猜、不静默填、不藏起来**。

- 这类条目在预览里**必须列出**，与「跳过」「失败」「超范围」都不同：复选框为 `[?]` 待绑定态，行内纯文本「待绑定 · 置信度 0.42」，值列显示 `--`。
- 主操作给「绑定类型 v」入口，点选后走拾取器同一套中文类型列表（§4.5），绑定完成即转为待填项并纳入本次计划；未绑定前不参与填充，汇总行单列「待绑定 N」。
- `unknown` 是哨兵，**不是生成器目标**，界面上不得显示为可生成值的字段类型。

**`E_UNSUPPORTED_CONTROL` 状态表达（v1.2）**：超范围控件在预览里单列分组，纯文本「跳过 · E_UNSUPPORTED_CONTROL · 控件超出 v1 适配范围」，并给「一键重新拾取」入口（跳到拾取器确认是否可归入已支持类型）。**不混进「失败」，避免用户误以为产品故障**；诊断报告同样单列（§4.6）。

列表用 1px `--border-soft` 分隔行，不用卡片网格（VISUAL_DENSITY 6）。

#### 防误填搜索框 / 筛选框的 5 层防线（本界面核心）

1. **作用域限定（源头排除）**：默认只扫描「最近的表单容器」（`<form>` / `[role="dialog"]` / Ant Design `.ant-modal`），搜索框、筛选框通常位于表单容器之外，天然不进入计划。顶部作用域条显式写出当前作用域名称，并提供「当前弹窗 / 当前表单 / 整页」三档切换，**默认最窄档**。用户切到「整页」时汇总行旁给纯文本提示「整页模式包含搜索与筛选控件，请逐项确认」。
2. **显式排除规则**：命中 `type=search`、placeholder / label / aria-label 含「搜索 / 查询 / 筛选 / 关键字」、name / id 含 `search|keyword|filter|query`、位于 `[role="search"]` 或表格工具栏容器内的 input，一律进入「已排除」分组，默认不勾选。
3. **排除项可视化，不是静默忽略**：面板底部「已排除 N 项」可展开，逐条列出控件标签与排除原因，每条给「纳入本次」文字按钮。规则过严时可强制纳入，避免漏填。
4. **预览即确认**：所有待填项默认勾选，但必须点击「填充 N 项」才写入；每行显示**将要填入的具体值**，支持逐项取消勾选与批量反选（调研 B 的 Smart Autofill 做法）。
5. **保护已有内容**：控件已有值默认不覆盖，行内灰显纯文本「已有值，保留」；需显式打开「覆盖已有值」开关才纳入。呼应 Smart Autofill 的 existing content preserved by default 与基线「默认只填不提交」。

补充：填充前若页面结构 hash 与规则库记录不符，顶部出现 `--warn` 纯文本提示条「页面结构已变化，规则可能失效，建议重新校验」，不静默套用旧规则（基线 §3.1 规则漂移、§6.8 自愈）。

**其余交互**（v1.1 补 undo / 五态 / 并发 / 文案禁令）：

- 勾选变化 → 汇总行实时更新（tabular-nums，无跳动）；主按钮文案同步为「填充 N 项」。批量「全选 / 反选」后汇总栏浮出批量操作（§2.8）。
- 类型下拉可直接改字段类型，改动**写入页面级增量规则**（只存这几个字段的修正，呼应基线 L3），并给行内纯文本「配置已保存到本机」。此改动即时生效且可撤销（撤销后回到推断类型）。
- 填充执行中：主按钮进入 loading 并禁用（防双提交），每行状态从「待填」逐项翻为「成功 / 跳过 / 失败」，并保留控件类型标签；顶部出细进度文本「正在填充 7 / 18」，不用转圈动画。**用户重复触发填充时，后一次取消或排队前一次，不得叠加写入**（PRD §9 并发）。
- 填充完成：底部 sticky 出诊断摘要 + 启用 `f-undo-fill`「撤销本次填充」文字按钮，面板**不自动关闭**，便于核对。撤销前按钮为禁用态并给纯文本「填充后可撤销」。
- **跳过原因完整枚举（v1.2）**：只读 / 禁用 / 隐藏 / 文件 / 验证码 / **不在表单容器内** / 搜索框或筛选框排除 / 已有值保留 / 用户取消勾选 / **`E_UNSUPPORTED_CONTROL`（控件超出 v1 适配范围，单列分组）**。每条跳过行都要带其中一项，不允许只写「跳过」。低置信度字段**不属于跳过**，走独立的 `unknown` 待绑定态。
- **五态 + 两个新增分组态**：空（见下）/ 加载（3 至 5 条骨架行 + 「正在识别控件」）/ 错误（单控件赋值失败不中断其余填充，行内标「失败」+ 定位）/ 成功（诊断摘要 + 撤销入口）/ 权限拒绝（见下）；另需覆盖 `unknown` 待绑定分组与 `E_UNSUPPORTED_CONTROL` 超范围控件分组，二者都不计入「失败」。
- **权限拒绝态**：域名不在白名单或标签页未授权时，面板整体替换为纯文本「当前页面不在测试站点白名单内，未执行任何填充」+「查看白名单设置」文字链接，列表与填充按钮全部不渲染，不降级为「尽力填」。
- 列表超过 100 项虚拟滚动（PRD §9 目标支持上百控件）；超长标签 `text-overflow: ellipsis` + `title` 完整值；`min-width: 0` 保证 flex 子项可缩。
- 空状态：「当前作用域没有识别到可填控件。可切换作用域，或用可视化拾取器手动绑定。」+ 「切换作用域」「打开拾取器」两个文字按钮。
- **按钮文案禁令**：主按钮只能是「填充 N 项」，次操作为「取消」「撤销本次填充」「重新识别」「关闭」；不得出现「提交」「确定」「保存并提交」等诱导业务表单提交的文案（§2.8）。

### 4.3 界面三：popup（选数据集、看本次结果）

**尺寸**：宽 **360px**，高不超过 **560px**（Chrome MV3 上限 800×600，建议 300 至 400 宽）。单列纵向，首屏即核心操作，不自动弹出。

**结构（自上而下）**：

1. **顶栏**：扩展名「表单填充」+ `f-env-label` 环境标识纯文本（「测试环境 · 已允许」/「非白名单域名 · 已停用」）。安全信号常驻，不折叠。
2. **数据集选择**：一行 `f-dataset-select`（初版仅「随机生成」一项，下拉结构预留，呼应基线 §3.2 DataProvider 扩展点）+ 等宽「本次种子 4821 · 可复现」+ 「换一组」文字按钮。
3. **主操作**：`f-btn-primary`「打开填充计划」+ 次按钮「可视化拾取」。与悬浮球同一路径，不提供「一键全填」。
4. **本次结果**：`f-result-summary` 纯文本 `成功 18 · 跳过 3 · 失败 1` + `f-undo-fill`「撤销本次填充」文字按钮（仅本次会话内有效，失效时置灰并说明）+「查看明细」展开 → 三个 `f-result-group` 分组列表；**每条明细都带控件类型纯文本标签**；跳过项列原因，失败项列折叠的定位信息 +「重新拾取」文字按钮。
5. **底部**：文字链接「配置与规则库」（打开 options 标签页）、`f-kbd` 快捷键说明。

**文案**：写真实功能语义，不写英文欢迎语、假文填充、空洞口号之类占位。空状态写「本次还没有填充记录。打开填充计划，先确认要填哪些控件。」并带主按钮。结果区常驻「仅填入，不提交」。

**五态（v1.1）**：空（无历史记录，见上）/ 加载（读本地 storage 时 2 至 3 条骨架行）/ 错误（「读取本地配置失败，点击重试」）/ 成功（结果摘要 + 撤销入口）/ 权限拒绝（非白名单时主操作区禁用，顶栏显示「非白名单域名 · 已停用」并给「查看白名单设置」链接，不显示任何可填充入口）。

**零账号墙**：popup 不出现登录、注册、升级、付费、试用、账号同步、云状态任何入口或提示（竞品差评教训 §1.3）。无网络请求，结果摘要只从本地 storage 读取。

**强调色预算**：全屏仅 2 处，即主按钮 + 当前选中数据集的下划线。

### 4.4 界面四：options 配置页（别名词典 / 生成器开关 / 页面规则 / 导入导出与本地统计）

**形态**：完整标签页（`options_ui.open_in_tab: true`），**左侧 Tab 导航 + 右侧内容区**（enterprise.md 经典后台布局，saas-b2b.md 设置页 Tab 分组），容器 `--container-max: 1080px`，桌面 12 列栅格 / gap 24px。

**Tab 分组（4 个，≤5 项符合工作记忆限制；v1.1 第 4 个 Tab 扩入本地统计）**：

| Tab | 内容 |
|---|---|
| 别名词典 | 约 20 类字段类型 → 别名列表。表格列：字段类型 / 别名 / 来源 / 操作；支持行内编辑、批量添加、搜索、按类型分组折叠 |
| 生成器 | 每类字段类型一行：启用开关（原生 switch）+ 参数（日期格式、号段、长度、字典来源）；停用行灰显纯文本标注「已停用」；高级参数折叠（渐进披露，每组 ≤4 可见字段） |
| 页面规则 | 按站点 / 页面指纹归档的**增量修正**列表，展示可读的控件标签与修正结果（**不展示静态选择器 / 正则 / XPath**，PRD §12）；状态纯文本「有效」/「结构已变化，建议重校验」 |
| 导入导出与本地统计 | 导出 JSON（规则 + 字典 + 生成器配置，**不含诊断计数与任何页面数据**）；导入 JSON 前先给校验结果预览「新增 N 条 / 覆盖 M 条 / 冲突 K 条」，确认后才写入；「恢复默认」二次确认；下方为本地诊断计数区（见下） |

#### 本地诊断计数区 `f-local-stats`（v1.1，PRD §10 / team-lead 裁决）

**只做纯文本计数展示，不做图表、不做趋势、不做数据看板、不做任何上报类界面。**

```
累计本地诊断计数 · 仅存于本机 · 自安装/上次清空以来
累计填充 1,284 项    跳过 96 项    失败 23 项
触发填充 42 次      拾取器改绑 7 次    规则漂移提示 3 次
最近一次 2026-11-09 14:32

[清空本地统计]
```

- **两类数字分属不同 storage 键，options 必须显式区分，不合并成一个「统计」面板**（ARCH-v1.1 §15.1 / ADR-004 决策四）：本区是**累计计数**（独立顶层键 `faf.counters.v1`，仅存 `LocalCounterRecord { event, count, lastAt }` 聚合数字，含 `field_unknown` 共 11 个事件）；popup「本次结果」是**单次结果**（`faf.lastResult.v1`）。二者口径不同——本区标题写明「累计 · 自安装/上次清空以来」，不要把「本次结果」的数字并进来，也不要让用户以为两者是同一个计数。配置类 `faf.rules.v1` / `faf.siteAllowlist.v1` / `faf.fabPosition.v1` 与结果/计数类严格不混存；`exportJson()` 不含计数、不含任何页面数据。
- 数字用 `tabular-nums` 等宽对齐；统计项与 PRD §10 的本地计数事件一一对应，界面只呈现聚合数字，不呈现事件名、维度明细或原始日志。
- **采集边界必须写在界面上**（纯文本，常驻不折叠）：「仅统计次数与结果分类，不采集字段取值、姓名 / 身份证等敏感值、页面 URL 明文（仅用指纹 hash）、IP 与页面原始输入；全部存于本机，零网络上报。」
- 「清空本地统计」为破坏性操作：二次确认，按钮文案「清空本地统计」，清空后给纯文本「本地统计已清空」，不用 toast、不做动画。
- **明确禁止出现的界面元素**：数据上报开关、云端统计、改善计划 / 体验改进计划、匿名数据收集、账号登录 / 注册 / 同步、看板与图表、付费墙与升级入口（§1.3、§2.8）。

**预留位（基线 §3.2）**：DataProvider / `presets` 配置 schema 初版不实现，但在「生成器」Tab 底部保留一个置灰折叠区，纯文本说明「预设字段值将在后续版本提供，当前始终使用随机生成」。UI 结构预留，不误导用户以为可用。

**安全区**：页面顶部独立「站点白名单」区块（域名 + 环境标识），删除 / 清空二次确认，纯文本警示「数据存于本机，不会上传；无账号、无云同步」。**存储口径统一为 `chrome.storage.local` 隔离存储 + 不上传 + 不写日志 + 导出脱敏**（不使用任何加密类措辞）；导出 JSON 不含诊断计数、字段取值与任何页面数据，默认只填不提交。

**交互规范**：

- 改动即时保存，无全局保存按钮（避免忘记点保存）；保存成功给行内纯文本「配置已保存到本机」短暂显示，不用 toast 弹窗。
- 每个字段有可见 label（不用 placeholder 当 label）、helper text、错误就近字段。
- 破坏性按钮命名破坏并二次确认，清单见 §2.8；撤销入口见 §2.8。
- 表格 1px 分隔行，行 hover 显操作，批量勾选后顶部浮出操作栏。
- **五态（v1.1）**：空（字典 / 规则 / 计数为空，各给具体引导文案，计数空态写「尚无填充记录」）/ 加载（骨架行）/ 错误（导入 JSON 给第几行哪个字段的解析错误，保留用户输入不清空；本地配置读取失败给「读取本地配置失败，点击重试」）/ 成功（行内「配置已保存到本机」）/ 权限拒绝（白名单为空时顶部纯文本警示「尚未添加测试站点，扩展不会在任何页面执行填充」+「添加站点」入口，不隐藏功能、不降级为尽力填）。

### 4.5 界面五：可视化拾取器（悬浮高亮 + 点选绑定字段类型）

借 DevTools Inspect 模式的骨架，按政务低饱和与「只存增量修正」精简。

**激活与常驻信号**：`Alt+Shift+P` / 悬浮球右键 / popup「可视化拾取」进入。激活后页面顶部出现 **`f-picker-toolbar` 常驻条**（非弹窗、不遮挡内容）：`--brand-ink` 实底、白色文字「拾取模式 · 点击控件绑定字段类型 · Esc 退出」+「已绑定 3 项」+「完成」按钮。工具条用品牌实色，明确这是扩展的 chrome 而非宿主页内容。

**hover 高亮**：目标控件叠加绝对定位 overlay（不改宿主页元素样式，避免触发联动重渲染）：**2px `--accent` 实色描边 + 8% `--pick-fill` 功能性半透明填充**（低饱和政务蓝，不用 DevTools 高饱和蓝）。所有 overlay `pointer-events: none`，不拦截宿主页交互。

**就近 tooltip `f-picker-tooltip` 只显示 4 项**（拒绝 DevTools 的信息过载；v1.1 移除元素路径）：

```
控件标签：联系电话
控件类型：输入框
推断类型：手机号   置信度 0.91
所属位置：新增人才弹窗 · 第 3 行    点击绑定字段类型
```

**信息边界（v1.2，ARCH ISOLATED world 硬约束）**：tooltip 与绑定面板**只能展示 DOM 文本与属性**，可读字段集合固定为 `label` / `placeholder` / `name` / `id` / `aria-label` / 邻近文本 / `maxlength` / `pattern` / 枚举 `option`。**没有组件实例、没有框架字段名、没有「组件内部状态」**。推断类型来自上述可见文本 + 别名词典 + 打分，界面上不得出现「自动识别组件库」「读取组件状态」「连接 Vue 实例」之类文案，也不要把「控件类型」标签描述成组件库识别结果（它只是 DOM 结构启发式判定）。

**不暴露选择器（v1.1，PRD §11 L202 / §12）**：tooltip、绑定面板、页面规则 Tab **一律不显示 CSS 选择器 / 正则 / XPath / DOM 路径**，也不提供任何让用户输入选择器的输入框。定位改用用户读得懂的「所属表单 + 所在行 + 控件标签」。元素路径只作为**诊断报告失败项的折叠信息**供开发者排障（§4.6），不进入拾取流程。规则主键是页面指纹，不是静态选择器。

**点击绑定（不超过 3 次点击）**：第 1 次点击目标控件 → 就近展开 `f-binding-panel`，列出 **`docs/contracts/field-types.json` 权威枚举的 20 类字段类型中文名**（带搜索框，可按中文名或别名搜索）→ 第 2 次点选类型即写入**页面级增量规则**（只存「这个页面这几个字段的修正」，基线 L3）；若需搜索，输入搜索词算第 3 次交互，仍不超过 3 次。写入后控件高亮切为 `--success` 描边 + 纯文本「已绑定：手机号」，工具条计数 +1。无「下一步」「确认」「保存」等额外步骤。

**字段类型权威枚举（v1.2，逐项对齐 `docs/contracts/field-types.json`）**：绑定面板、预览类型下拉、options 别名词典三处一律以本表为准，不得自行增补。

| key | 中文名 | key | 中文名 |
|---|---|---|---|
| `personName` | 人名 | `gender` | 性别 |
| `idCard` | 身份证 | `phone` | 手机号 |
| `landline` | 座机 | `email` | 邮箱 |
| `date` | 日期 | `time` | 时间 |
| `region` | 省市县 | `address` | 详细地址 |
| `organization` | 单位名称 | `school` | 学校 |
| `education` | 学历/学位 | `jobTitle` | 职称/职务 |
| `code` | 编号编码 | `amount` | 金额 |
| `quantity` | 数量 | `percentage` | 百分比 |
| `dictEnum` | 字典枚举 | `longText` | 长文本备注 |
| `unknown` | 待绑定哨兵 | | |

- `unknown` 是**哨兵，不是生成器目标，也不作为绑定面板的可选项**；它只表示「置信度低于 0.6 未硬猜」，用户从上面 20 类中选一类完成绑定（PRD AC-5）。
- 一致性组 `identity`（`idCard` / `date` / `gender` / `personName`）在同一种子下必须来自同一条记录；界面上同组字段若被分别改绑，给纯文本提示「身份证、出生日期、性别、人名需保持同一条数据，已同步更新」。
- `region` / `organization` 等类型在契约里带 `cascader root` / `remote-search select` 特征，但这些**控件形态超出 v1 适配范围**（`E_UNSUPPORTED_CONTROL` 单列分组，控件类型标签仍按 ARCH §17.6 归「下拉」/「其他」），字段类型可推断、控件不可填，界面不要把「字段类型」「控件类型」「是否纳入 v1」三件事混为一谈（§4.2）。

**绑定可撤销**：工具条常驻「撤销上一次绑定」文字按钮；撤销后该控件回到推断类型，计数 -1，规则同步移除该条增量修正（§2.8 undo 基线）。

**键盘可达（不能只靠 hover/点击）**：`Tab` 在候选控件间移动、`Enter` 打开绑定面板、方向键在类型列表中移动、`Enter` 确认、`Ctrl+Z` 撤销上一次绑定、`Esc` 退出。焦点始终有 3px `--focus-ring`。

**修饰键**：`Shift` 强制拾取 `pointer-events: none` 的组件包装层（借 DevTools）；`Ctrl` 临时隐藏 tooltip。

**不可绑定态**：hidden / disabled / readonly / file / 验证码 / 提交按钮 hover 时用 `--border` 虚线描边 + 纯文本「不可绑定：只读」，点击无反应，不误写入规则。

**五态（v1.1）**：空（当前页无可绑定控件，工具条提示「当前作用域没有可绑定控件」+「切换作用域」）/ 加载（识别中给「正在识别控件」纯文本）/ 错误（规则写入失败给「本页规则保存失败，点击重试」，不丢失已选类型）/ 成功（「已绑定：类型」+ 计数）/ 权限拒绝（非白名单页面根本不进入拾取模式，悬浮球与 popup 入口给出明确拒绝提示）。

**退出与联动**：`Esc` 或「完成」退出；有未保存绑定时给纯文本确认。退出后拾取器里绑定的类型**立即回写填充计划预览对应行**（含控件类型标签），用户回到面板即可见，形成「推断错 → 点选修正 → 计划更新 → 再填充」闭环。

### 4.6 专项：填充结果「成功 / 跳过 / 失败」如何呈现

三处呈现，逐级收敛，全部用 `f-status` 纯文本（§2.6）：

| 位置 | 呈现 |
|---|---|
| 1. 预览面板执行中 | 每行状态列实时从「待填」翻为「成功 / 跳过 / 失败」，150ms 颜色切换，无动画；**每行保留控件类型纯文本标签**；`unknown` 未绑定与超范围控件不参与写入 |
| 2. 预览面板底部 sticky | 汇总 `成功 18 · 跳过 3 · 超范围 1 · 失败 1`（等宽数字）+ 纯文本「已填充 18 项，未提交」+ `f-undo-fill`「撤销本次填充」；全成功无 toast、无庆祝 |
| 3. popup「本次结果」 | 持久化摘要 + 四个可展开分组，逐项明细，**每条带控件类型标签与错误码（如有）** |
| 4. 诊断报告（team-lead 定稿：不新增独立界面） | 不新增第 6 个界面；作为状态载体复用填充计划结果态与 popup 明细，按**成功 / 跳过 / 超范围控件 / 失败**四组展开，支持一键定位与重新拾取 |

**「成功」必须由回读确认驱动**（PRD §12 假成功坑；ARCH-v1.1 §14.2 三层回读）：状态列只能由 `FillResult.verified === true` 驱动，禁止由「已派发 `input` / `change`」「进度计数」或任何中间态驱动。三层证据 `domValueMatched` / `frameworkStateMatched`（派发 `change` 后等两个渲染帧值未被框架回滚）/ `validationCleared` **全部为真**才 `verified=true`；任一为假一律 `status='failed'` + `E_READBACK_MISMATCH` 并写明失败层。**UI 文案里「成功」的含义是「三层证据均通过」**，不写成「已读取 Vue / React 组件 state」或「读到组件内部状态」——ISOLATED world 读不到组件实例，第 2 层只是可观测等价证据、两个渲染帧是时序近似，不是直接读 state。

**诊断报告错误码（v1.2，PM / team-lead 裁决）**：

| 错误码 | 含义 | 归属分组 | 界面呈现 |
|---|---|---|---|
| `E_UNSUPPORTED_CONTROL` | 控件超出 v1 适配范围（仅支持原生控件 + Ant Design Vue / Element Plus 指定主版本的 `select` / `date-picker`） | **超范围控件，单列** | 「跳过 · 控件超出 v1 适配范围」+「一键重新拾取」，**不混进「失败」** |
| `E_READBACK_MISMATCH` | 赋值后回读 DOM 值与预期不一致 | 失败 | 「失败 · 回读校验未通过」+「定位到元素」+「重新拾取」 |
| `E_SITE_NOT_ALLOWED` | 域名不在业务白名单 | 权限拒绝（整屏） | 「当前页面不在测试站点白名单内，未执行任何填充」 |
| `E_BRIDGE_UNAVAILABLE` | MAIN world 桥接不可用（ARCH §2.2 降级路径，架构文档已有） | 失败（降级记录） | 纯文本记录，不阻断其余控件填充 |

- 错误码在明细里用 `--font-mono` 小字显示，后面必须跟一句中文原因；**不能只甩一个码给用户**。
- `unknown` 未绑定项在结果里单列「待绑定 N（未参与填充）」，不算跳过、不算失败、不算超范围。

**跳过必须带原因（v1.2 完整枚举）**：只读 / 禁用 / 隐藏 / 文件 / 验证码 / **不在表单容器内** / 搜索框或筛选框排除 / 已有值保留 / 用户取消勾选 / **`E_UNSUPPORTED_CONTROL`（单列分组）**。原因以 `--meta` 小字跟在「跳过」之后，如「跳过 · 只读」「跳过 · 不在表单容器内」。低置信度字段走 `unknown` 待绑定态，不列入跳过。

**失败必须带定位与出路**：

- 主操作为「定位到元素」文字按钮：点击后滚动宿主页到该控件并给出 2 秒高亮描边（PRD §14 验收要求「失败项可一键定位到元素」）。
- 折叠区「查看定位信息」内才显示 `--font-mono` 元素路径 + 「复制定位图标」（16px），**默认折叠**，普通用户不接触选择器；这是元素路径唯一允许出现的位置（§4.5）。
- 「重新拾取」文字按钮：直接跳到拾取器并预选该控件，用户 2 次点击内完成改绑。超范围控件同样给此入口（仅用于确认是否可归入已支持类型）。
- 呼应基线 §3.1 诊断报告与 §6.8「失败降级模糊匹配并提示重新拾取，而不是静默填错」。

**不靠颜色单一传达**：每个状态的文字本身即语义，颜色只是加速识别；失败项额外提供可操作出口。

**五态 + 两个分组态（v1.2）**：空（无填充记录）/ 加载（骨架行 + 「正在识别控件」）/ 错误（单控件失败不中断其余填充，逐项列原因与错误码）/ 成功（汇总 + 撤销入口）/ 权限拒绝（`E_SITE_NOT_ALLOWED`，不产生任何结果，给明确拒绝文案）；另需单列 `unknown` 待绑定与 `E_UNSUPPORTED_CONTROL` 超范围控件两组，二者均不计入失败。

**常驻提示与文案禁令**：面板与 popup 结果区都保留「仅填入，不提交」；结果态不出现任何「提交」「确定」「保存并提交」类主按钮（§2.8）。

| `f-input` / `f-select` | 1px `--border-control` | 边框 `--accent` | 3px ring + 边框 `--accent` | 输入中 | `--surface-warm` 底 | 不适用 | 边框 `--danger` + 就近错误文字 | placeholder 仅作提示，label 常驻 | 行内「已保存」纯文本 |
| `f-plan-row` | 1px 分隔行 | `--surface-warm` 底 | 3px ring（键盘） | 选中 `--accent-soft` 底 | 灰显（排除/已有值） | 骨架行 | 不适用 | 见面板空状态 | 状态列「成功」 |

| `f-picker-highlight` | 2px `--accent` 描边 | 同（跟随） | 3px ring 于焦点控件 | `--success` 描边（已绑定） | 虚线 `--border` 不可绑定 | 不适用 | 不适用 | 不适用 | 纯文本「已绑定：类型」 |

5 态覆盖补充：

- **Loading**：预览扫描中显示 3 至 5 条骨架行（不用转圈）；填充中显示进度文本而非动画。
- **Empty**：计划无控件 / popup 无历史 / 字典无别名 / 规则库为空，均写具体引导文案 + 操作按钮，不写空洞占位。
- **Error**：storage 读取失败给「读取本地配置失败，点击重试」；JSON 导入失败给第几行哪个字段；填充失败给元素定位 + 重新拾取。
- **Populated**：正常列表，超过 100 项虚拟滚动。
- **Edge**：超长控件标签 `ellipsis` + title；失败项 100+ 折叠「显示剩余 N 项」；超长数据集名截断；整页模式控件数超 200 时提示「控件较多，建议缩小作用域」。

**PRD 五态与本文 9 态矩阵的映射（v1.1）**：

| PRD 五态 | 对应 9 态 | 组件级要求 |
|---|---|---|
| 空 | Empty | 具体引导文案 + 操作按钮，不报错、不执行填充 |
| 加载 | Loading | 骨架行 / 进度纯文本，不用转圈、不阻塞其余操作 |
| 错误 | Error | 具体原因 + 重试入口；单控件失败不中断整体 |
| 成功 | Success | 诊断摘要 + 撤销入口，无 toast、无庆祝动画 |
| 权限拒绝 | Disabled 的强化态 | **必须带原因纯文本**（「当前页面不在测试站点白名单内」），不隐藏功能、不降级为「尽力填」；`f-btn-primary` / `f-plan-row` / `f-picker-highlight` / `f-popup` 统一为 `--surface-warm` 底 + `--meta` 字 |

新增组件状态补充：

- `f-control-type`（控件类型纯文本标签）：纯静态，不参与 9 态，无 hover / focus / 颜色变化，避免与状态标签混淆。
- `f-undo-fill`「撤销本次填充」：Default（填充完成后可用）/ Hover / Focus（3px ring）/ Active / Disabled（会话快照失效，置灰 +「页面已变化，无法撤销」）/ Loading（撤销中纯文本）/ Success（「已撤销本次填充」）。
- `f-local-stats`：Empty（「尚无填充记录」）/ Populated（纯文本计数）/ Loading / Error（读取失败可重试）/ Success（「本地统计已清空」）。

## 7. 每个界面的设计提示词（供 Phase 2 细化与前端实现）

> 以下 5 段可直接作为前端 Agent 的实现提示词。共同前提：Product 寄存器、默认浅色、`--token` 引用、**唯一 SVG 图标来源已锁定为 `@lucide/vue@1.70.0`**（架构师在 ARCH-v1 §3.4 正式锁定，PRD §9 L181 / ADR-001 同口径；离线内联 SVG、具名导入 tree-shake，`lucide-vue-next` 已 deprecated 禁止入依赖，见 §3.1）、状态与控件类型均为纯文本、`f-` 组件前缀、150ms 反馈、`prefers-reduced-motion`、focus-visible 3px ring、触摸目标 44px 起、零 emoji。

> **v1.2 共同前提补充（5 段全部适用）**：① 悬浮球 / 拾取器为 `activeTab` + 用户手势**按需注入**，非打开页面即常驻，首次须按 `Alt+Shift+F` / `Alt+Shift+P` 或点工具栏扩展图标，页面刷新后需再次触发；② 控件类型标签 `f-control-type` 取值固定为 `ControlType` 5 类中文映射 `输入框 / 下拉 / 日期 / 文本域 / 其他`（ARCH-v1.1 §17.6），与字段类型（`FieldType` 20 类 + `unknown`）是两列正交、互不覆盖；「超范围控件 / `E_UNSUPPORTED_CONTROL`」是结果面板处置状态分组，不写进类型标签，cascader / 远程搜索 select 归「下拉」但单列超范围；v1 仅支持原生控件 + Ant Design Vue / Element Plus 指定主版本的 `select` / `date-picker`；③ 字段类型以 `docs/contracts/field-types.json` 为权威枚举（20 类 + `unknown` 哨兵，置信度 < 0.6 标「待绑定」供点选绑定，不硬猜）；④ 结果面板错误码 `E_UNSUPPORTED_CONTROL`（超范围控件单列，不混进失败）/ `E_READBACK_MISMATCH` / `E_SITE_NOT_ALLOWED` / `E_BRIDGE_UNAVAILABLE`，超范围项给「一键重新拾取」；⑤ 拾取器信息边界只到 DOM 文本与属性（无组件实例 / 框架字段名）；数据 `chrome.storage.local` 隔离存储 + 不上传 + 不写日志 + 导出脱敏，默认只填不提交。

**v1.1 补充前提（以下 5 段全部适用，不再逐段重复）**：

- **R1 控件类型**：计划预览行、执行中状态列、诊断报告明细、popup 结果明细四处都要有 `f-control-type` 纯文本标签，取值固定为 `ControlType` 5 类中文映射 `输入框 / 下拉 / 日期 / 文本域 / 其他`（ARCH-v1.1 §17.6 / `contracts/types.ts`，L1 扫描必须返回）；与字段类型 `FieldType` 两列分别展示、互不覆盖。无图标、无语义色。v1 仅支持原生控件 + Ant Design Vue / Element Plus 指定主版本的 `select` / `date-picker`；cascader / 远程搜索 select 归「下拉」但超出 v1 范围，与富文本、自定义复合控件一起标 `E_UNSUPPORTED_CONTROL` **单列分组**（结果面板处置状态，不是控件类型标签、不占成功率分母）。跳过原因必须带完整枚举，含「不在表单容器内」。
- **R2 五态**：每个界面都要实现 空 / 加载 / 错误 / 成功 / 权限拒绝，权限拒绝必须给原因纯文本，不隐藏功能、不降级为尽力填（逐界面细则见 §4.7）。
- **R3 交互基线**：填充可撤销（填充前快照控件原值，撤销恢复）；破坏性操作二次确认且按钮命名破坏；批量操作需选中态 + 汇总计数；4 组快捷键 + Esc + Ctrl+Z；重复触发填充不得叠加写入。
- **R4 拾取器**：一次类型改绑不超过 3 次点击；tooltip、绑定面板、规则 Tab 均不显示 CSS 选择器 / 正则 / XPath / DOM 路径；元素路径仅出现在诊断报告失败项的折叠区。
- **R5 零上报**：不实现任何云同步、账号、登录、数据上报、改善计划、看板图表、付费墙界面；options 只做本地诊断计数纯文本展示与一键清空，明确不采集字段取值与 URL 明文。
- **R6 图标**：文档与 aria-label 用文字化含义（「注入图标」「字段拾取图标」「诊断报告图标」），英文图标名只作实现映射；状态标签与控件类型标签零图标。
- **R7 文案禁令**：预览、结果、popup 三处主按钮不得出现「提交 / 确定 / 保存并提交」；常驻「仅填入，不提交」。
- **R8 隔离性**：Shadow DOM 隔离、不改宿主页 DOM 结构、不注入全局样式、不写页面全局对象、**不向宿主页控制台输出任何日志或警告**、扩展异常不阻塞被测页面；注入层不加载外部字体、固定扩展自身主题。

## 8. 可访问交互与认知负荷

> 按 `design-commands.md` §5「a11y 审计分离原则」，本轮只给设计期基本要求，对比度精确校验、屏幕阅读器播报、ARIA Role 等留给 Phase 2 的 `audit` 命令专项执行。

**设计期基本要求**：所有交互 `:focus-visible` 3px `--focus-ring`；5 个界面全键盘可达，`Esc` 统一关闭浮层；触摸目标 ≥44×44，按钮间距 ≥8px；状态不只靠颜色（纯文本 + 原因，§2.6）；所有图标按钮 `aria-label`；`prefers-reduced-motion` 降级到静态；不使用 `user-scalable=no`。

**认知负荷检查**：

- 导航顶级项：popup 2 个操作 + 2 个链接、options 4 个 Tab，均 ≤5。
- 决策点：预览面板每屏可见选项虽多，但已按「待填 / 已排除 / 已跳过」分块，且提供「仅看待填」筛选，把可见决策降到 1 组。
- 表单每组 ≤4 可见字段（options 高级参数折叠）。
- 主操作 1 个（填充 N 项）+ 1 至 2 个次操作，其余收进菜单。
- 一次一事：识别 → 预览核对 → 确认填充 → 看诊断，四步各自独立，不要求用户跨屏记忆。

**角色化红旗抽查（选 3 个最相关）**：

| 角色 | 关注 | 本设计的应对 / 剩余风险 |
|---|---|---|
| 亚历克斯（急躁高手） | 跳过引导、快捷键、批量 | 已给 4 组快捷键、批量反选、类型下拉直接改、可选「跳过预览直接填充」（默认关）。剩余风险：若 Phase 2 把预览做成强制多步向导，会被嫌慢 |
| 山姆（无障碍依赖） | 键盘、焦点、非颜色状态 | 已给全键盘路径、focus ring、状态纯文本 + 原因、拾取器 Tab 遍历。剩余风险：content script 注入层的焦点管理需前端实测，宿主页可能劫持 Tab |
| 莱利（压力测试者） | 空状态、静默填错、错误暴露 | 已给排除项可视化、结构漂移提示、失败元素定位 + 重新拾取、JSON 导入校验预览。剩余风险：结构 hash 阈值需架构师定义，过灵敏会频繁误报 |

凯西（移动用户）不适用：本工具是桌面浏览器扩展。但需处理小窗口（popup 固定 360px、面板 ≤72vh、options <1024px Tab 转顶部）。
