# ADR-004: v1.1 裁决批次 - P0 组件适配器内建、三层状态回读与零遥测

## Status

Accepted (2026-11-09)

## Background

首轮 ARCH-v1 把 Ant Design Vue / Element Plus 的非原生控件适配列为「高成本 / P2」，依据是方案 v0.3 第 4 节把它们放在 P2。PM 在 PRD-v1 中把「最小可用集」（select / date-picker 能填 + 赋值后组件内部状态与校验态确实生效）上提到 P0，理由是政务表单主体就是非原生控件，初版不支持则零配置可用率接近 0。team-lead 裁决采纳，并要求「把 Filler 与组件适配器放进 P0 核心链路的模块契约，不要设计成后期可插拔的补丁」。

同时 team-lead 裁决另两条硬约束：禁止裸 `el.value = x`、填充后必须回读组件内部状态、未生效判失败（`FillResult` 带 `verified`）；以及零网络上报、不设计任何外发 / 埋点 / 遥测模块、诊断计数只落本地 storage。PM PRD-v1.1 与设计师 UIUX-v1.1 随后补齐了控件类型枚举、undo 快照、结果态由回读驱动、拾取器不暴露选择器、计数与配置分键等约束。

本 ADR 记录这批裁决落到架构层的决策。它们不改变 ADR-002 的执行世界结论，也不改变 ADR-003 的 DataProvider 接口。

## Decision

**决策一：6 个 P0 填充策略是内建核心链路，不是可插拔插件。**

入口装配期无条件注册 `native-input` / `native-select` / `ant-design-vue-select` / `ant-design-vue-date-picker` / `element-plus-select` / `element-plus-date-picker`，`Filler` 构造时校验，缺一即抛错。`register()` 只对 P2 之后新增的适配器开放。理由：把 P0 能力做成插件会允许「先交一个只能填原生 input 的壳」这种假交付，而 PM 已证明该壳的零配置可用率接近 0。完整适配（远程搜索、级联、跨页面会话）仍留 P2。

**决策二：状态回读用可观测证据，且只有唯一错误码。**

ISOLATED world 读不到框架 state 对象（ADR-002 背景第 1、3 条），因此「校验组件内部状态」定义为三层可观测证据：`domValueMatched` / `frameworkStateMatched`（派发 change 后等两个渲染帧，值未被框架回滚）/ `validationCleared`。三者全真才 `verified = true`；任一失败为 `status='failed'` + `code='E_READBACK_MISMATCH'`，失败层写在 `failureReason`。PRD AC-3 与 UIUX R13 也用 `E_READBACK_MISMATCH`，故 `types.ts` 移除首轮多余的同义校验失败码，避免三份文档出现两个同义码。UI 成功态只能由 `verified === true` 驱动，不得以「事件已派发」驱动。

**决策三：联动稳定判定用 `MutationWaiter`，不用固定 `setTimeout`。**

`MutationObserver` + predicate + `AbortSignal` + `LINKAGE_TIMEOUT_MS = 3000` 超时兜底。`setTimeout` 在架构中只保留为 `requestIdleCallback` 不可用时的分批调度回退，两者不得混用。唯一性校验类字段串行写入并限速，防止打爆页面异步校验。

**决策四：不存在任何遥测模块；计数与配置 / 结果分键。**

禁止 `fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` / `sendBeacon` / 远程字体与脚本 / 统计 SDK / 远端规则库。本地计数只写 `faf.counters.v1`，11 个事件（含 PM 新增的 `field_unknown`），只存 `{event, count, lastAt}` 聚合数字，不采字段取值、URL 明文、IP、页面原始输入。`faf.rules.v1` / `faf.fabPosition.v1` / `faf.siteAllowlist.v1`（配置）与 `faf.lastPlan.v1` / `faf.lastResult.v1`（结果）与计数严格分键；`exportJson()` 不含计数；options 只展示聚合纯文本数字 + 一键清空。`E_UNSUPPORTED_CONTROL` 单列统计，不混入成功率分母。

**决策五：UI 注入层与撤销的工程契约。**

Shadow DOM 隔离 + 固定扩展自身主题 + 注入层不加载外部字体 + popup 360x560 + 4 条 `commands`（F/G/H/P）+ `RuntimeMessage` 通道且结果落 storage。undo 快照只在 content script 内存会话，不落盘、不进计数；撤销走**与填充相同的 `FillerStrategy`**（非原生控件恢复组件内部 state，而非只写隐藏 input），回读校验；快照失效时 `UndoState.valid = false`，UI 置灰并给「页面已变化，无法撤销」。确认原生 setter + 冒泡事件足够，**不需要组件实例通道**（组件实例通道在 v1 不可行，ADR-002）。

**决策六：公共枚举与阈值单一来源。**

20 类字段类型以 `docs/contracts/field-types.json` 为唯一权威；`ControlType` 5 类（输入框 / 下拉 / 日期 / 文本域 / 其他）与字段类型正交；`CONFIDENCE_THRESHOLD = 0.6`（正式锁定）、`VIRTUAL_SCROLL_THRESHOLD = 100`、`MAX_FIELDS_PER_PAGE = 200`；结构漂移用 override 唯一命中率 + Jaccard `< 0.85` 连续 2 次 + 7 天防抖，避免误报刷屏。规则主键是 `urlPattern + structureHash`，`FieldLocator` 移除 `css` / `xpath`。

## Consequences

**正面**

- P0 交付不再有「只填原生 input」的降级空间，政务表单主体控件在初版即可用；组件适配器与 Filler 在同一份契约里，识别层 / 执行层零改动。
- 三层回读把「脚本报绿、业务没生效」变成可断言的失败路径，且三份文档共用一个错误码，UI 不需要写兼容分支。
- 零遥测 + 分键存储让政务内网的合规说明可以直接落到 manifest 白名单与 storage 键，不需要额外审计模块。
- undo、控件类型、拾取器边界都在契约层有对应类型，前端不需要自行发明状态。

**负面 / 代价**

- 6 个 P0 适配器 + `StateVerifier` + `MutationWaiter` + `UndoManager` 让初版工作量明显高于「只做原生 input」，这是 team-lead 明确接受的 P0 范围扩大。
- 三层回读每层都依赖组件库 DOM 细节（portal 容器 class、`aria-invalid`、错误提示节点），组件库升级可能使证据失效；缓解：14.4 锁定页面侧版本锚点，第 18 章兼容性矩阵作为升级前后的回归门禁。
- 「两个渲染帧」仍是渲染时序的近似，不是对框架 state 的直接读取；若某页面在两帧之后才回滚，第 2 层会误判通过。缓解：`verification.evidence` 记录信号名、`attempts` 上限 2 次、诊断报告允许人工标记，且第 18 章变异测试专门覆盖此场景。
- 计数与配置 / 结果分键后，options 的「本次结果」与「累计计数」来自两个键，UI 需要显式区分两类数字，不能合并成一个「统计」面板。
- 撤销对非原生控件要求走同一适配器，意味着 6 个策略都要实现反向操作，工作量翻倍；不做这一步则撤销只改隐藏 input、界面显示旧值，属于新的假成功。

**复核点**：第 18 章第 1 条（变异测试）、第 11 条（undo 闭环）、第 6 条（零外发）任一失败即重审本 ADR 对应决策。
