# ADR-002: 填充主路径留在 ISOLATED world，MAIN world 仅作可选增强；采用 activeTab 用户手势按需注入

## Status

Accepted (2026-11-09)

## Background

基线方案 v0.3 的 6.1 节把「Vue2 补 `el.__vue__`、Vue3 取 `__vueParentComponent`」列为受控组件解法，3.1 节把「组件实例桥接」列为填充层能力。要判断这两条能不能落地，必须先回答 MV3 的执行世界问题。

联网核实的四条硬事实（详见 `ARCH-v1.md` 第 2 章与附录 A）：

1. content script 运行在 ISOLATED world，页面 JS 挂在 DOM 元素上的 expando 属性不共享。Chrome 官方文档明确 web page / content scripts / 其他扩展三者互相都访问不到对方的变量；独立研究与实测进一步确认 `el.__vue__` 这类 expando 在 content script 里恒为 `undefined`。跨 world 共享的只有 DOM 结构、标准属性、`dataset`、DOM 事件、`window.postMessage`。
2. `chrome.scripting.executeScript({ world: 'MAIN', files: [...] })` 可行（Chrome 95+），但需要 `scripting` 权限 + `host_permissions` 或 `activeTab`；MAIN world 脚本**没有扩展 API**（WXT 官方原文）；MAIN world 受**宿主页面 CSP** 约束，而 ISOLATED world 受**扩展自己的 CSP** 约束。
3. Vue 3 生产构建默认不暴露 `__vueParentComponent`（`__VUE_PROD_DEVTOOLS__` 默认 false）；Vue 2 的 `el.__vue__` 只在组件根元素上，普通 `<input>` 不持有。两者都是非公开内部字段，随版本漂移。
4. React 的 valueTracker 用 `Object.defineProperty` 定义在**元素实例**上，原型 setter 仍是原生实现。ISOLATED world 有自己的 DOM wrapper 原型，不会被页面框架 patch，因此从 ISOLATED world 取到的就是干净原生 setter；DOM 事件跨 world 共享，页面监听器能收到 `dispatchEvent` 派发的冒泡事件。

第 4 条意味着一件反直觉但重要的事：**原生 setter + 派发 `input`/`change` 这套填充主路径，在 ISOLATED world 里就能完整跑通，根本不需要 MAIN world 注入**。

同时产品有两个安全约束：站点白名单（只填测试环境）、默认只填不提交、人工触发。若按常规做法静态声明 `content_scripts` 配 `matches: ["<all_urls>"]`，会要求宽泛 `host_permissions`，安装期出现「读取和更改所有网站上的数据」警告，与企业环境策略冲突。

## Decision

**决策一：v1 填充主路径固定在 ISOLATED world。**

- L1 扫描、L2 推断、L3 拾取、生成器、Filler、FillPlanner、FillExecutor 全部在 ISOLATED world 的 content script 中运行。
- 统一填充原语为原型原生 setter `.call(el, value)` + 冒泡 `input` + 冒泡 `change` + 回读校验；textarea 用 `HTMLTextAreaElement.prototype`，checkbox/radio 用 `el.click()`。
- 不依赖任何 Vue/React 组件实例私有字段。基线方案 6.1 的组件实例解法与 3.1 的「组件实例桥接」从 v1 主路径移除。

**决策二：MAIN world 降为 P3 可选增强通道，且必须可降级。**

- 只有后续确实需要读取页面 JS 上下文（例如 P3 的项目内 SDK 钩子探测、devtools 风格元数据）时才启用。
- 实现形态用 WXT 的 `defineUnlistedScript` 生成 `page-bridge.js` + content script 里 `injectScript('/page-bridge.js', { keepInDom: true })`，并把脚本列入 `web_accessible_resources` 的 `resources` + `matches`（MV3 两者缺一不可）。不使用 `world: 'MAIN'` 的静态 content script，因为那样连扩展 API 都没有。
- 通信固定三段式：MAIN -> `window.postMessage({ channel, requestId, payload })` -> ISOLATED（校验 `event.source === window`、channel、`requestId` 配对、字段白名单）-> `chrome.runtime` -> background。桥接不传身份证、预设值等敏感数据。
- MAIN world 一律用 `files` 注入打包好的静态文件；禁止内联 `<script>`、`eval`、`new Function`、远程代码。注入失败或页面 CSP 拒绝时，`BridgePort.available = false`，所有调用返回 `E_BRIDGE_UNAVAILABLE`，填充流程照常完成。

**决策三：精准填充通道改为「页面主动暴露」的 SDK 钩子，不靠偷偷读组件实例。**

自研系统在 dev/test 环境主动挂 `window.__FORM_FILLER__ = { getFields, setValue }`，扩展检测到钩子时优先走它，否则降级到 DOM 方案。走 `FillerStrategy` 注册表接入，识别层/执行层零改动。定级 P3，v1 不实现。

**决策四：权限模型采用 activeTab + 用户手势按需注入，不声明 `host_permissions`。**

- `permissions: ["activeTab", "scripting", "storage"]`。官方 activeTab 文档列出的合法用户手势包含 `commands` 快捷键与 action 点击，与本产品「人工触发」形态一致。
- v1 不静态声明 `content_scripts`。WXT 中把主 content script 作为 unlisted script 打包，由 `background.ts` 在 `chrome.commands.onCommand` / `chrome.action.onClicked` 中调用 `chrome.scripting.executeScript({ target: { tabId }, files: [...] })` 注入（默认 ISOLATED）。
- 不使用 WXT 的 `registration: 'runtime'`：其官方文档说明该模式会把 `matches` 加入 `host_permissions`，与决策四冲突。
- 站点白名单是**业务层**，与 `activeTab` 的**权限层**独立：填充前校验 `location.hostname` 命中白名单或含 `test`/`uat` 环境标识，不命中返回 `E_SITE_NOT_ALLOWED`，不写任何字段。
- `minimum_chrome_version` 设 `120`，覆盖 `world: 'MAIN'`（95+）、动态注册（102+）并留出企业环境余量。

**v1.1 补充（P0 组件适配器与状态回读）**：team-lead 裁决把 Ant Design Vue / Element Plus 的 select / date-picker 最小适配集上提到 P0，作为 `Filler` 的 6 个内建策略之一（ARCH 14.1），不是可插拔插件；本 ADR 决策一的「统一填充原语」不变，但补充：赋值后必须走三层状态回读，`FillResult.verified` 是唯一成功判据，失败统一记 `E_READBACK_MISMATCH`（14.2 / ADR-004 决策二）。这两点不改变执行世界结论——所有适配器仍在 ISOLATED world 运行，仍不依赖组件实例私有字段。

## Consequences

**正面**

- v1 复杂度显著下降：不需要跨 world 通信、不需要 `web_accessible_resources` 里的桥接脚本、不需要处理页面 CSP 差异。
- 权限申请最小：安装期无「读取所有网站数据」警告，企业策略拦截概率下降；权限只在用户明确按键/点击时临时生效，页面导航或关闭即回收。
- 主路径不依赖框架内部私有字段，抗 Vue/React 版本升级与生产构建差异。
- 安全边界清晰：MAIN world 的额外攻击面被推迟到 P3，且默认关闭、可降级。

**负面 / 代价**

- **页面刷新后扩展不自动注入**，需要再按一次快捷键或点一次扩展图标，悬浮球才出现。这是权限最小化的直接交换，必须写进产品说明并由 PM 同步给用户。若用户更看重「打开页面即常驻」，需改用静态声明 + 显式测试域名白名单 `host_permissions`，但会重新引入安装期权限警告。**注意「架构层不变」只指分层与模块契约（ARCH 第 5-9 章）不变**：2.6 manifest 字段、5.3 注入策略、本 ADR 决策四、15.2 权限白名单门禁、16.2 首次唤起步文案这 5 处必须定点修订，不能只改 PRD。
- 「组件实例精准填充」无法作为通用能力承诺；Ant Design Vue / Element Plus 的非原生控件只能靠独立 `FillerStrategy` 适配，v1 限定 2 个库指定主版本的 select / date-picker，其余返回 `E_UNSUPPORTED_CONTROL`。
- 合成事件 `isTrusted === false`，个别业务风控可能忽略；只能靠回读校验 + 诊断报告标记，无通用解法。
- 三段式 postMessage 通道在 P3 启用后仍可被页面伪造（官方 DevTools 文档明确 "not foolproof"），所以桥接永远不传敏感值，且不作为填充成败的必要条件。

**复核点**：第 12 章端到端验证第 5 条（React 受控输入提交 payload 非空）是决策一成立的关键断言；第 10 条（桥接注入失败仍完成填充）是决策二可降级的关键断言。任一失败即重审本 ADR。
