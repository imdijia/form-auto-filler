# ADR-001: 使用 WXT 0.21.5 + Vue 3 + TypeScript 作为浏览器扩展工具链

## Status

Accepted (2026-11-09)

## Background

形态已锁定为 Chrome/Edge MV3 扩展，无后端。项目当前状态：`D:/myTools/form-auto-filler/` 只有方案文档，无 `package.json`、无 `node_modules`。本机实测 `node v22.22.2`、`pnpm 10.2.1`。用户是 Vue 3 / TypeScript 前端，日常用 pnpm。

本项目的代码构成里，绝大部分是**与 UI 无关的纯逻辑**：L1 结构扫描、L2 类型推断、20 类生成器、填充策略、分批调度、规则库读写。UI 只出现在 popup、options 和悬浮球/拾取器。所以工具链必须同时满足两件事：能把纯逻辑层拆成可单测的 TS 模块，又能把多个扩展入口（background / content / popup / options / unlisted script）打包成一个合规的 MV3 扩展包。

同时 MV3 对 `manifest.json` 的字段（`world`、`commands`、`options_ui`、`web_accessible_resources`、`content_security_policy`）要求精确，工具链不能把 manifest 藏在无法覆盖的抽象后面。

专家团定的是**规则**（`ARCH-v1.md` 3.1 节 R1-R8），具体选型由架构师在满足规则的候选中做。本 ADR 记录这次选定。

## Decision

在满足 R1-R8 的候选中，本项目的工具链选定为：

| 项 | 选定 | 锁定版本 |
|---|---|---|
| 扩展框架 | WXT | 0.21.5 |
| UI 框架 | Vue | 3.5.45 |
| 语言 | TypeScript | 5.9.3 |
| 构建 | Vite | 8.3.6 |
| Vue SFC 插件 | @vitejs/plugin-vue | 6.0.10 |
| 包管理 | pnpm | 10.2.1 |
| 图标库 | @lucide/vue | 1.70.0 |

对比矩阵（`ARCH-v1.md` 3.2 节，满分 90）：WXT 88、CRXJS 76、Plasmo 66、原生 JS 无构建 59。

关键依据：

- WXT 官方支持 `vue` 模板，Vite 驱动，TypeScript 优先，`wxt.config.ts` 可直接写 manifest 字段（R1/R2/R3）。
- `defineContentScript` 支持 `world` 与 `registration`，`defineUnlistedScript` + `injectScript` 提供 MAIN world 桥接能力，`createShadowRootUi` 提供悬浮球/拾取器的样式隔离（R4）。
- 所有逻辑随扩展包本地打包，符合 MV3 CSP 与商店政策（R5）。
- 纯逻辑层可以不 import `vue` / `wxt/browser` / `chrome.*`，脱离扩展环境单测（R6）。
- registry 原始 JSON 核实：`wxt@0.21.5` 的 `engines.node >=22` 与本机一致，peer 为 `vite ^6.3.4 || ^7 || ^8`、`typescript >=5.4`（R7/R8）。

不选取的理由：

- **原生 JS 无构建**：没有类型与模块化，无法执行「单文件 <= 300 行 + 纯逻辑层可单测」的组织纪律。仅适合 0.5 天油猴验证，不作交付工程。
- **Vite + @crxjs/vite-plugin 3.0.0**：registry 确认已发正式版且 peer 覆盖 Vite 8，不再是长期 beta，不选取的原因不是「不稳定」，而是它只是单 Vite 插件，多入口目录、manifest 装配、unlisted script 注入都要自建并长期维护，对本项目是额外一层装配成本。
- **Plasmo 0.90.5**：React 优先、类 Next.js 约定较厚；团队是 Vue 3，且较厚抽象让纯逻辑层解耦多绕一层。其 `dependencies` 固定 `typescript: 5.8.2`、`@parcel/core 2.9.3`，与本项目的版本锚定也不一致。

图标库单独锁定 `@lucide/vue@1.70.0` 为全项目唯一 SVG 图标来源。registry 明确 `lucide-vue-next@1.0.0` 带 `deprecated: "Package deprecated. Please use @lucide/vue instead."`，任何 Spec 或代码出现该包名即判不合格。

**v1.1 补充（图标引入方式与许可证合规）**：team-lead 裁决正式采用 Lucide 为全项目唯一图标库，架构师在 `ARCH-v1.md` 3.4 锁定，设计侧推荐与 team-lead 裁决结论一致，尺寸规范 / 语义白名单 / 状态纯文本规则不返工。**PRD §9 L181 与 UIUX R9 均已硬锁定 Lucide / `@lucide/vue@1.70.0`**，三份文档在库名、版本、离线内联、禁 `lucide-vue-next` 四项上完全一致；首轮「PRD 按 PM 边界不写库名」的理解已被 team-lead 裁决 5 覆盖，**作废**（由 PM 回确认触发，见 ARCH 3.4 口径更正）。引入方式为构建期具名导入 + tree-shake，产物是随扩展包打包的**离线内联 SVG**，运行时不走 CDN、不发起任何网络请求（与 15.1 零外发一致），不受宿主页 CSP 影响；不引入第二套图标库，不加载远程字体。许可证 ISC：发布包内保留 `@lucide/vue` 的 LICENSE 与版本号、不剥离版权声明；ISC 无 copyleft 传染，不要求开源扩展自身代码。分工上 `ARCH-v1.md` 3.4 是**实现细节**的唯一权威，PRD / UIUX 是产品与设计侧的硬锁定结论；§0 第 5 条 / 4.1 版本表 / 15.1 打包清单 / §13 设计师行均只引用 3.4。

TypeScript 锁定 5.9.3 而非 registry `latest` 7.0.2：WXT peer 只要求 `>=5.4`，TS 7 是跨代版本，初版不引入未经验证的编译器变更；升级需单独验证并先改版本表。

## Consequences

**正面**

- 多入口、manifest、按需注入、MAIN world 桥接、Shadow DOM UI 都有官方支持，不需要自研装配层。
- 纯逻辑层与 UI 层解耦，`docs/contracts/` 下按职责拆分的六组接口可以脱离浏览器单测。
- 团队沿用 Vue 3 + TS + pnpm，学习成本集中在 WXT 的 entrypoint 约定，不在新语言或新框架。
- 版本锚定到具体补丁号，配合 `pnpm-lock.yaml` 可复现构建。

**负面 / 代价**

- WXT 0.21.x 仍是 0.x 主版本，跨小版本可能有 breaking change；升级必须重新跑第 12 章端到端验证。缓解：lockfile 锁定精确版本，不设 `^` 范围自动升级。
- WXT 约定（`entrypoints/` 目录命名、entrypoint 自动发现）会约束目录结构，`src/` 下不能随意放会被误识别为入口的文件。缓解：`ARCH-v1.md` 5.2 节已给出目录规范，实现按此组织。
- 引入构建层意味着调试时要区分 `.output/chrome-mv3` 产物与源码；manifest 必须由构建生成后复核，禁止手写产物。
- 图标库只有 Lucide 一套，设计稿里不属于 Lucide 的图形需要走 `src/ui/brand/` 单独审批，设计自由度收窄。

**需要复核的触发条件**：团队技术栈变化（R3）、任一依赖被标记 deprecated 或 registry 版本不可用（R7）、Node 运行时低于 22（R8）。触发时按同一矩阵重新评分，架构层（分层、契约、字段类型、规则库）不依赖具体构建工具，可整体保留。
